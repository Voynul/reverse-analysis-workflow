# 报告语言规范

## 基本语言

- 正文使用中文。
- 代码名、字段名、类名、方法名、包名、URL、文件路径、公司名、组织名、产品名保留原文。
- 第一次出现难懂技术词时，补充白话解释。

## 证据语言

写结论时应说明证据来自哪里：

- 反编译代码。
- 抓包数据。
- Hook 日志。
- 配置文件。
- 解密结果。
- Native 函数、反编译伪代码或人工还原的伪代码说明。

证据不足时使用：

```text
当前证据不足，需补充确认。
```

不得使用：

```text
应该是
可能就是
大概率
看起来像
```

除非明确标注为待确认推断。

## 禁用表达

报告不写开发修复建议，不写安全、隐私、风险、合规等审计式评价。

如果来源材料中有这类词，应改写为中性技术事实。

以下词语不得作为确定评价直接使用：

- 安全风险。
- 隐私风险。
- 合规风险。
- 欺诈。
- 反作弊。
- 风控。
- 恶意。
- 绕过。
- 检测缺失。
- 高危。

如果来源材料中包含上述词语，应优先改写为中性技术事实；无法中性改写时，放入待确认问题，不写成评价性结论。

如果上述词语是代码、字段、接口、配置、用户问题或计划目标中的原始术语，可以保留原文，但必须说明它在当前证据里的具体含义，不得把术语本身当成评价结论。

术语白名单中的词按 `naming-rules.md` 处理，不强制改写。

推荐改写：

| 原表达 | 推荐表达 |
|---|---|
| 风控数据 | 设备和运行环境信息 |
| 风控用途 | 可用于区分请求环境 |
| 缺失 Root 检测 | 未发现 Root 状态采集逻辑 |
| 反作弊检测 | 请求环境识别 |
| 欺诈检测 | 异常请求识别 |
| 安全风险 | 可观察到的技术行为 |
