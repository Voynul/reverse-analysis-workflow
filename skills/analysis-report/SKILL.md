# Analysis Report

本技能用于把一次小型分析、一个专题问题或大型任务中的某个阶段，整理成可读、可复查、可合并的普通分析报告。

## 项目规则

生成报告前，优先检查项目根目录是否存在 `项目规则.md`。

- 如果存在，读取并应用其中与报告结构、术语边界、重点范围、排除范围、证据文件和项目模板有关的约束。
- 如果不存在，跳过项目规则，按本 skill 和用户输入生成报告。
- `项目规则.md` 只能限定范围和表达要求，不能替代证据。

## 输入交接

如果报告来自 `android-reverse` 或其他分阶段分析计划，生成前应优先确认并使用以下材料：

- 本次分析计划文件。
- 项目规则文件。
- 独立 `证据索引.md`、证据目录或阶段材料。
- 命名记录，例如 `rename.md` 或混淆命名记录。
- 原始网络样本、配置样本、Hook 日志、运行日志、系统记录或静态代码位置。
- 待确认问题和工具或材料阻塞说明。

缺少上述材料时，只能标注为证据缺口或待确认问题，不能自行补造结论。

## 强制规则

1. 先选报告级别，再组织内容；报告级别见 `reference/report-levels.md`。
2. 每个关键结论必须有证据；证据、字段注释、核心流程和静态代码说明见 `reference/evidence-rules.md`。
3. 正文使用中文，代码名、字段名、类名、方法名、包名、URL、文件路径、产品名保留原文；语言边界见 `reference/language-rules.md`。
4. 标题、图表节点和总结尽量使用白话表达；术语白名单可直接使用，名称俗语化见 `reference/naming-rules.md`。
5. 涉及流程、关系、状态、时序或分支时必须配图；图表规范见 `reference/chart-rules.md`。
6. 报告先讲结论，再讲证据；核心小节末尾写 `总结：...`，短小节可以合并到上级章节总结；写作结构见 `reference/writing-style.md`。
7. 不写开发修复建议，不写安全、隐私、风险、合规等审计式评价；只描述可观察到的技术事实。
8. 正文只展开真实存在且有证据支撑的内容；已检查但未发现、不适用或材料不足的分析点，放在对应章节末尾简表中说明。

- 证据与字段规范：`reference/evidence-rules.md`
- 报告语言规范：`reference/language-rules.md`

## 输出自检

输出前检查：

1. 是否每个关键结论都有证据。
2. 是否存在猜测、占位符或示例数据冒充真实证据。
3. 是否包含必要图表。
4. 图表节点是否使用中文白话。
5. 是否正确处理已检查但未发现的机制和待确认问题。
6. 是否避免开发建议和审计式评价。
7. 是否选择了合适的报告级别，没有为小任务硬凑长报告。
8. 配置或参数字段含义是否贴着真实字段注释说明，并保留未注释原始证据。
9. 正文未展开的计划覆盖项，是否已用章节末尾简表说明未发现、不适用或待确认状态。
10. 结论摘要是否能独立阅读，并降低术语、缩写和 SDK 名称造成的理解门槛。
11. 核心流程结论是否在正文还原真实静态代码流程，并与真实网络数据、远程配置或缓存样本互相印证。
12. 静态代码、反编译代码、smali、调用链、关键方法或关键判断条件是否补充代码位置、功能、输入输出、影响和证据等级说明。
13. 是否按计划阶段完成证据确认，没有只凭字段名、类名、接口字段或 SDK 包名下确定结论。
