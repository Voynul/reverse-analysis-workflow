# Analysis Report

本技能用于把一次小型分析、一个专题问题或大型任务中的某个阶段，整理成可读、可复查、可合并的普通分析报告。

## 项目规则

生成报告前，优先检查项目根目录是否存在 `项目规则.md`。

- 如果存在，读取并应用其中与报告结构、术语边界、重点范围、排除范围、证据文件和项目模板有关的约束。
- 如果不存在，跳过项目规则，按本 skill 和用户输入生成报告。
- `项目规则.md` 只能限定范围和表达要求，不能替代证据。

## 强制规则

1. 正文使用中文。
2. 类名、方法名、字段名、包名、URL、文件路径、产品名保留原文。
3. 标题、图表节点、总结尽量使用白话表达。
4. 每个关键结论必须有证据。
5. 涉及流程、关系、状态或时序时必须配图。
6. 每个关键小节末尾必须写一句 `总结：...`。
7. 不写开发修复建议。
8. 不写安全、隐私、风险、合规等审计式评价。

## 报告级别

根据任务大小选择报告级别。用户未指定时，按证据复杂度自动选择最轻但完整的级别。

### 精简版

适用于一个接口、一个字段、一个方法、一个开关或一次 Hook 结果。

至少包含：

1. 分析目标。
2. 结论摘要。
3. 关键证据。
4. 待确认问题。
5. 一句话总结。

### 标准版

适用于一个完整专题，例如广告预加载、配置读取、某条网络链路或一组相关字段。

至少包含：

1. 分析目标。
2. 结论摘要。
3. 关键流程或关系图。
4. 详细分析。
5. 关键证据。
6. 字段、配置或参数说明。
7. 已检查但未发现的机制。
8. 待确认问题。
9. 证据索引。
10. 一句话总结。

### 阶段版

适用于大型逆向任务中的阶段产物。阶段版在标准版基础上增加：

1. 本阶段范围。
2. 与前后阶段的关系。
3. 可供最终报告合并的核心结论。
4. 后续阶段需要补证的问题。

## 结构取舍

- 小型报告不强制写“已检查但未发现的机制”；只有实际检查过、用户问过或读者容易误解时才写。
- 证据索引默认保留；精简版可压缩为 2 到 5 行小表。
- 图表不是每篇强制；涉及流程、关系、状态、时序或分支时必须配图。
- 普通分析报告不负责合并多份报告；多报告汇总交给 `final-report`。

## 输出自检

输出前检查：

1. 是否每个关键结论都有证据。
2. 是否存在猜测、占位符或示例数据冒充真实证据。
3. 是否包含必要图表。
4. 图表节点是否使用中文白话。
5. 是否正确处理已检查但未发现的机制和待确认问题。
6. 是否避免开发建议和审计式评价。
7. 是否选择了合适的报告级别，没有为小任务硬凑长报告。
