# Android Reverse 工作状态规范

## 定位

`.android-reverse/` 是长任务、跨会话任务或修改任务按需存放内部状态和中间产物的可选工作目录，不是项目正式交付目录，也不能改变外部调用者已有的文件规划。简单分析默认在当前 Agent 任务上下文维护状态，不创建该目录。

文件存放优先级从高到低为：

1. 用户明确指定的路径。
2. 外部项目 plan、`项目规则.md` 或上层调用技能指定的路径。
3. 报告类技能规定的输出位置。
4. `android-reverse` 默认的 `.android-reverse/` 内部目录。

外部已经规划的报告、脚本、证据、命名文件或其他产物继续写入其指定位置。不要将它们迁移、复制或重定向到 `.android-reverse/`；需要使用时只在内部状态中记录引用路径。

只有任务确实需要持久化并且能够可靠确定项目根目录时才创建 `.android-reverse/`。无法确定时，不要在任意当前目录创建工作区；在当前 Agent 任务上下文维护状态即可。

## 可选结构

    .android-reverse/
    ├── analysis-state.md
    └── targets/
        └── <包名>_<版本号>_<APK文件名>/
            ├── rename.md
            ├── notes.md
            ├── scripts/
            ├── evidence/
            └── outputs/

`analysis-state.md` 用于恢复目标确认、任务模式和关键进度。目标目录中的其他文件按需创建，不要求全部存在。

## analysis-state.md

根据任务需要记录以下状态，不要求无关字段：

- 当前活动 APK 的绝对路径。
- 包名、`versionName` 和 `versionCode`。
- 用户是否已经确认目标。
- 任务模式：`analysis`、`runtime-validation` 或 `patch-and-verify`。
- 交付物：对话结论、脚本、修改 APK、验证记录或正式报告。
- 已使用工具的目标、关键状态、版本或连接方式；未使用工具不记录。
- 关键逻辑归属：DEX、资源、native、React Native/Hermes、Flutter、Unity、WebView、服务端或待确认。
- 正式报告策略：`required` 或 `not-required`；用户未要求时默认 `not-required`。
- 报告策略的作用域：当前 APK 或用户明确指定的项目级默认值。
- 外部 plan、项目规则或上层技能指定的文件路径引用。
- 已打开的 native database/session、目标二进制、用途和可选保存路径。
- 长任务轨道：分析、修改、构建、安装、运行验证分别记录 `not-started`、`in-progress`、`passed`、`failed`、`blocked` 或 `not-applicable`。
- 当前阻塞原因、已重复次数和下一种不同的验证方法。
- 当前目标状态：分析中、已完成或已中止。

只读分析通常使用 APK 绝对路径、包名、`versionName` 和 `versionCode` 确认身份。修改模式必须额外记录原始 APK 的文件大小和 SHA-256，并为每个输出产物记录独立身份，不能覆盖原始 APK。

## 正式报告策略

正式报告策略不应打断简单任务：

- 用户已经明确说明时直接记录，不重复询问。
- 用户未说明时默认 `not-required`，直接回答当前问题。
- `not-required` 表示不自动调用 `analysis-report` 或 `final-report`，不表示禁止生成其他文档。
- 用户可以随时修改报告策略；修改后立即更新状态。
- 用户切换 APK 后沿用默认策略；只有用户明确要求正式报告时才改为 `required`。

## 目标管理

默认聚焦一个已确认目标。版本对比、split APK 集合、宿主与插件或动态载荷分析可以同时涉及多个文件，但必须为每个目标记录独立身份，并避免混用证据、工具状态和输出产物。

下列情况视为用户主动切换：

- 用户明确说切换到另一个 APK。
- 用户提供新的 APK 绝对路径并要求开始新的分析。

`jadx-headless` 中检测到目标变化但用户没有说明时，不视为授权；先输出新目标的身份信息并等待确认。用户只提到另一个包名、版本或文件名作为线索时不自动加载；明确要求比较时，将其作为独立目标加入当前任务。

切换前：

1. 将旧目标标记为已完成或已中止。
2. 保存 Agent 判断需要复用的轻量中间材料。
3. 不因 APK 切换终止无关联的 `idalib-mcp` worker。
4. 为新目标确认 APK 身份、任务模式和逻辑归属。
5. 只有需要持久化时才创建新的目标工作目录，避免中间产物混用。

## idalib-mcp session 状态

`idalib-mcp` session 与 APK 没有强制对应关系。仅记录无头 session：

| 字段 | 说明 |
|---|---|
| session/database | 工具返回的标识 |
| binary_path | 目标二进制绝对路径 |
| opened_by | 已知创建者或 `unknown`，不因会话存在就推定归当前任务所有 |
| related_apk | 可选的 APK 路径或包名 |
| purpose | JNI 链路、独立 so 分析等 |
| idle_ttl_sec | 无头 worker 的空闲退出时间 |
| saved_idb_path | 可选的数据库保存路径 |

Agent 不通过系统命令终止 worker；无头 worker 由 `idle_ttl_sec` 和服务端生命周期机制退出。

## 修改模式状态

`patch-and-verify` 额外记录：

- 原始 APK 身份和只读备份位置。
- 对照重建产物及其安装、启动结果。
- 修改声明：目标文件、符号、偏移或资源、预期行为和修改原因。
- 输出 APK 路径、哈希、签名信息和构建日志。
- 安装、冷启动、目标路径和回归检查结果。
- 未完成项、残留命中和不能验证的原因。

## 清理

- 技能默认不删除任何文件，也不因任务完成自动清理工作目录。
- 用户明确要求清理时，先解析并列出准确目标范围，再执行获准的删除。
- 不删除用户提供的 APK、so、正式报告、关键证据或用户明确要求保留的文件。
- 不使用清理操作覆盖或替换原始 APK；修改产物进入独立输出目录或用户指定目录。
