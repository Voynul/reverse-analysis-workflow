# 请求签名与算法验证

## 何时读取

任务要求还原请求签名、加解密或离线算法时使用。验证规模按目标和现有证据决定，不强制工具、样本数量、台账或额外报告；本地还原任务无须执行线上请求。

## 从真实输入输出开始

将同一次调用的输入、输出及影响计算的上下文对应起来，避免混用不同请求的 body、时间戳、nonce、token 或密钥版本。只有密文或签名值、缺少配对输入时，先记录缺口，不用自拟数据证明算法正确。

区分业务对象、序列化后的字节和最终网络内容。压缩、URL 编码、字段重排或 header 注入可能发生在不同阶段，抓包中的显示文本不一定就是算法输入。

## 按实现确认字节语义

只检查实际影响目标计算的项目：

| 层面 | 容易遗漏的差异 |
|---|---|
| 输入构造 | 字段顺序、排序规则、分隔符、空值与缺省值、重复字段、末尾换行 |
| 序列化与编码 | 原始 body 与重新生成的 JSON、字符串与嵌套对象、数字格式、字符编码、URL 编码时机 |
| 密钥与参数 | 原始字节与 hex/Base64 文本、派生过程、IV/nonce、填充方式、初始化和跨调用状态 |
| 输出格式 | 原始字节、hex 大小写与前导零、Base64/Base64url、截断位置及长度 |

库缺少算法时报告具体缺失，不换成其他算法后沿用原名。补齐、截断密钥或默认生成 IV 等行为，只有与目标实现一致时才用于复现。

算法常量、输出长度和函数名用于形成候选，不足以证明真实调用链。自定义变换可以直接按其语义还原或调用已定位函数，不必先给它套上标准算法名称。

## 自身签名证书参与计算时

目标读取自身证书，或重签名后出现接口、解密或初始化差异时，可以检查：

- 证书读取结果是否真正进入摘要、密钥派生、签名输入或缓存状态。`Signature`、`SigningInfo`、`toByteArray()`、`toCharsString()` 等仅作定位线索；读取证书不等于一定存在校验或派生。
- 核对实际使用的证书、摘要和编码字节，不把 `META-INF/*.RSA` 容器直接当成应用读取值；证书选择与转换过程以目标代码、可靠解析或运行样本为准。
- 有条件时比较原包、零逻辑修改重签包和业务修改包，在同一输入及可比上下文下观察最早出现差异的环节。异常值或请求失败本身不能确定原因，仍需排除会话、网络和输入差异。
- 根据用户目标和已确认的数据流决定兼容处理，不默认在全部读取点硬编码原证书，也不因诊断需要自动扩大修改范围。缺少真实读取值时记录缺口，不从文件大小或字符串外观猜值。

这类诊断可先离线进行，不要求发送线上请求。方法参考：`apk-reverse-codeberg-mirror` 中 `apk-reverse` 的 `references/signature-derived-keys.md`；仅吸收输入溯源与对照验证，不继承其统一替换方案。

## 选择能区分假设的验证

- 优先复算已有的配对样本；需要判断泛化能力时，再选择其他独立样本或有针对性的输入变化，不固定验证轮数。
- 确定性输出可逐字节比较。涉及随机化输出时，按真实随机量和算法语义选择可比方式，不要求每次结果相同。
- 不匹配时，在可取得的边界比较输入长度、编码和中间结果，定位最早出现差异的位置。尚未观测到的中间值保留为推断，不为匹配样本随意调整规则。
- 区分独立实现、调用原应用函数和模拟执行原二进制。后两者可以满足离线调用目标，但不能直接宣称算法已独立重写。

## 说明验证到了哪里

| 已有证据 | 可以说明 | 不能直接说明 |
|---|---|---|
| 一个配对样本匹配 | 该样本下结果一致 | 其他输入、版本或会话均正确 |
| 独立样本或对照验证 | 已检查条件下的计算规则得到支持 | 线上服务一定接受请求 |
| 授权范围内的实际请求结果 | 该环境、账户和时刻的服务端表现 | 失败一定源于签名，或成功代表所有分支成立 |

线上验证仅在任务确实需要且已获授权时执行。签名匹配但请求失败时，分别检查已有证据涉及的 token 生命周期、nonce 重用、时钟、请求顺序、权限和传输差异，不直接归因为某种防护。保留离线验证结果及未验证范围即可。

复现材料按用户要求交付；敏感密钥、token 和明文不直接展示在对话或普通日志中，使用引用或脱敏说明。

方法参考：`owen800q/mobile-reverse-skill@d905f7d` 的 `references/signing-replay.md`。已独立整理验证方法，不依赖其 `sign_rebuilder.py`、台账或阶段关卡。
