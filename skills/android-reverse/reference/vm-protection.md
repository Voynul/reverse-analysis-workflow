# VMP / 私有字节码与解释器分析

## 何时读取

目标出现虚拟化保护、私有字节码或解释器线索时使用。VMP 可与 DEX、JNI、Unity 等运行时叠加；先确认具体保护层，不依据产品名套用固定寄存器、opcode 表或解密方案。

本文件提供多条可选路线。任务可能只需解释一个分支、观测输入输出或复现局部计算，无须先恢复整个虚拟指令集。

## 确认虚拟化与层次

有助于判断的关联证据包括：载荷中的指令读取、虚拟 PC 的推进、分发目标、虚拟寄存器或栈状态，以及 handler 对状态的读写。单个大 switch、间接跳转、native 声明或反编译失败都不足以确认 VM。

区分以下情况：

- 普通状态机或 OLLVM 控制流平坦化：分发状态主要决定宿主基本块顺序，尚无被解释的指令流证据。
- native VM：解释器消费载荷并更新虚拟状态；解释器本身也可能被平坦化，外层分发器与 VM 分发器需要分开。
- DEX 虚拟化或方法抽取：目标实现可能仍位于改写后的 DEX，也可能已移入其他载荷或解释器，不能从方法体外观直接决定恢复方式。

出现解码异常时，先检查格式、版本、指令边界和解析器覆盖，必要时用独立工具交叉检查；解码器错误不能作为私有指令集的证据。

## 从可观察的数据进入

- 可从真实输入、输出、目标缓冲区、错误路径或业务调用点追踪消费者，避免仅沿混淆后的宿主调用图扩大范围。
- 按任务需要识别载荷基址、虚拟 PC、寄存器或栈状态、分发方式和宿主调用边界。布局通过使用方式与状态变化验证，不从另一目标复制。
- 表项为空或不像指针时，检查重定位、编码及运行时初始化；不直接认定为加密。
- x86 的虚拟标志、寄存器及指令惯用法不能直接套用于 ARM 目标。位运算、无分支选择等应按实际读写和计算效果理解，不能只凭指令混合判定算法。

## 定向轨迹与语义切片

需要动态证据时，可以围绕一次目标调用、线程和输入采集有限轨迹。记录模块与地址空间、寄存器变化和相关内存读写；存在递归、嵌套 VM 或多线程时分别维护上下文。

有跳采、循环压缩、排除模块或丢失事件时，说明覆盖缺口。零事件不证明目标未执行；不完整轨迹不能当作全部语义。

可以从返回值、虚拟状态或内存写入反向切片，逐步识别操作数、数据来源、PC 更新和宿主调用。恢复语义时核对位宽、符号扩展、部分写入、字节序及副作用；不能默认虚拟指令遵循宿主 CPU 的同名行为。

## 按目标选择恢复方式

| 目标与条件 | 可选路线 | 验证重点 |
|---|---|---|
| 理解局部条件或数据处理 | 数据流分析、定向轨迹及 handler 切片 | 输入如何影响输出或状态，不把宿主分支当成原始业务分支 |
| 需要可重复调用的计算 | 原函数调用、模拟执行或独立还原 | 区分实现方式，核对初始化、宿主依赖和真实输入输出 |
| 需要可读的虚拟程序 | 恢复部分 handler 语义并表示为 IR 或解释器 | 核对指令长度、控制流及逐步状态，未恢复部分保留未知 |
| 已有可配对的保护前后产物 | 差分推导部分私有 opcode 或编码规则 | 先验证方法对应、边界与转换假设，再用未参与推导的数据检查 |

差分路线不能默认指令长度不变、opcode 一一替换或规则跨构建稳定。识别 opcode 名称不等于恢复操作数、寄存器分配和可重建方法；不把阅读骨架当可安装代码。

从单次轨迹抽取的计算可能只覆盖某条路径。时间、nonce、设备状态和常量表若被固化，应说明适用条件，不把单样本复现升级为通用算法。

## 可调用的抽取程序

当目标是确定性局部计算时，可以比较恢复完整解释器与抽取最小可执行数据流的成本。输入相关节点保留，已证明与输入无关的计算可折叠；不能仅因为某次运行走了一条路径就删除其他分支。

抽取结果应配套保留程序/IR、常量表及基准、输出位置映射和固定输出模板，并绑定同一来源构建。缺少输出拼装信息时，局部计算正确也可能产生错误签名或消息。

验证位宽、符号/零扩展、部分寄存器写入、内存副作用与宿主调用 ABI；在有区分力的真实输入和必要中间点比较。来自单次设备状态的常量只支持该条件，不当成算法固有参数。
