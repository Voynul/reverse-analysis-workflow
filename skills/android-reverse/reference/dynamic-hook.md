# 动态 Hook 规范

## 适用场景

- 获取方法参数、返回值、异常和真实分支。
- 获取加密前明文、解密后明文、签名材料、序列化对象。
- 验证静态分析推断是否在运行时成立。
- 追踪 Java 到 native 的入参和返回值。
- 配合抓包确认请求字段来源。
- 必要时修改返回值观察行为变化，但结论中必须标注这是主动干预后的结果。

## 可选观察路线

1. 利用已有静态、运行或协议证据确定或探索目标，包括原始类名、方法名、重载签名和调用时机。
2. Frida 脚本必须使用运行时原始名称；JADX/JEB 重命名只用于阅读。
3. 记录当前判断需要的时间、线程、参数、返回值、异常或调用栈，不默认采集全部内容。
4. 输出建议使用 JSONL，便于后续筛选和报告引用。
5. 需要触发路径时选择实际可用的操作方式，并记录与样本关联的动作。
6. 需要确认网络影响时，将可取得的流量与 Hook 条件对应。

## 操作与故障分流

连接、CLI、版本与 RPC 接口见 [Frida 工具](tools/frida.md)。出现 attach 后退出、零事件或卡住时，参照 [反分析诊断](topics/anti-analysis.md) 区分进程状态、工具链、脚本、消息通道与目标检测，不默认叠加隐藏模块。

只需要函数输出时，可比较原函数调用、RPC 和模拟执行，见 [调用与模拟](topics/rpc-emulation.md)。指令级证据参照 [native 轨迹](topics/native-tracing.md)，普通参数观测无须进入该分支。

## 日志格式

推荐 JSONL：

```json
{"ts":"2026-01-01T00:00:00.000Z","type":"HOOK","class":"原始类名","method":"原始方法名","args":{},"ret":{},"stack":"可选"}
```

对大对象只保留当前问题需要的内容，并避免在对话或日志中暴露无关敏感数据。不要把示例日志当成真实证据。

## Hook 生成要求

- 根据原始类名、方法名和完整参数类型选择目标，不使用阅读阶段创建的语义别名。
- 遇到重载时保存明确的 overload handle，并通过该 handle 调用原始实现。
- 根据目标实际情况处理构造器、静态方法、自定义 ClassLoader、异步调用和 native 方法。
- 先观察原始行为，再进行返回值替换或参数修改；两类结果分开记录。

## 注意事项

- Hook 重载方法时必须写清参数类型。
- Frida 使用原始混淆名，报告使用 `原名→新名`。
- 修改返回值会改变行为，必须把原始结果和干预结果分开记录。
- Hook 日志只能证明运行时观察到的路径，不自动证明所有分支。
