# Flutter / Dart 分析

## 何时读取

目标功能进入 Flutter、Dart snapshot 或 AOT 编译代码时使用。按目标和现有证据选择路线，不要求先尝试 Java Hook、构建反编译器或安装专项工具。

## 确认业务层与产物

- `libflutter.so`、`libapp.so`、Flutter assets 和平台入口是候选线索。结合包结构与加载代码区分引擎、Dart 业务代码、资源和 Android 插件；不要把所有行为都归入 Dart。
- 识别实际构建形态：AOT 产物、可用的 kernel/snapshot 或其他加载形式。Java/Kotlin 平台通道、插件和 WebView 仍可能参与功能。
- 对 split 集合、多 ABI 或热更新产物，匹配引擎、业务产物及实际版本。修改验收覆盖用户要求的运行范围，不要求每个分析任务处理所有 ABI。

## 版本与工具选择

snapshot 格式、ABI 和构建选项会影响解析结果。优先使用产物中的引擎信息、snapshot 标识及结构证据交叉判断；工具推测的兼容配置名不一定等于原始 SDK 版本。

需要解析 snapshot 时，可以选择当前环境中兼容的前端，例如 blutter、aotopsy 或其他已验证能力。只有普通反汇编结果时，也可以先追踪已知入口和平台交接，不要求为继续任务先获得完整对象池。

工具成功退出只说明处理完成。抽查可识别的字符串、函数边界、对象布局或调用关系，确认输出与目标相符；版本不支持或解析失败时记录缺口，不能据此认定没有业务代码。

## 从线索定位代码

- 从目标相关的字段、URL、提示文本或资源开始，结合对象池引用、注解反汇编、调用关系和运行样本缩小范围。字段名也可能属于协议或框架，读取周边数据流后再命名。
- 字符串可能采用单字节、UTF-16 或 snapshot 对象表示。按实际布局检查编码、长度和边界；某种编码搜索未命中不等于字符串已被删除。
- 区分文件偏移、ELF 虚拟地址、运行时地址和工具重建的对象池偏移。它们不能默认通过同一个常量相互换算。
- 对象池条目列表不等于引用列表。工具声称零引用时，结合其支持的指令形式和已知引用点检查覆盖范围，再决定是否能排除使用。
- 对照参数、返回值和读写方向，区分请求构造、反序列化和本地决策；必要时追踪 Dart 与插件或 native 代码的交接。

## 解释结果与修改验证

- Dart 对象、带标签的数值、布尔值和压缩指针应按当前版本及架构解释；不要直接套用 C 整数返回值或另一版本的寄存器、字段偏移。
- 共享字符串、对象池常量或通用序列化逻辑可能影响多个消费者。修改前确认所需范围，选择合适控制点，不规定统一的数据修改或分支修改方案。
- 修改 native/AOT 字节时确认地址空间与原始指令，重建后从最终产物回查目标位置。具体构建和运行验收见 `patch-and-verify.md`。
- 请求算法复现按需参照 `algorithm-validation.md`；恢复对象池或生成函数列表不等于业务逻辑已还原。
