# Native 层分析规范

## 触发条件

出现以下线索时可进入 native 专题，再根据所需操作选择实现：

1. Java 层调用 `native` 方法。
2. 发现 `System.loadLibrary` 或 so 加载逻辑。
3. 关键参数、签名、加密、解密、校验进入 `.so`。
4. 用户明确要求分析 so、JNI、native 函数或导出符号。
5. Frida Hook 发现 Java 层入参和返回值之间缺少解释，需要看 native 内部。

## 分析要求

- 检查反编译结果，并根据分析需要添加注释。
- 根据后续分析和可读性需要决定是否重命名变量、函数或其他符号；用户明确要求时优先执行。
- 如有必要，更改变量和参数类型，尤其是指针和数组类型。
- 如果需要更多细节，分解函数并添加注释说明发现。
- 地址、大小和数值变换使用可审计计算，注明地址空间和单位，不凭心算得出高风险结论。
- 不要尝试暴力破解，应基于反汇编、伪代码、交叉引用和简单脚本推导。
- 不强制创建 `native-report.md`；是否落盘由用户要求、正式报告策略或 agent 的复用需要决定。

## 操作与专题

打开、会话、查询和保存操作见 [native 工具](tools/idalib.md)，工具可用性不决定经验方法是否适用。关联来源明确时可分析目标库；多个合理候选无法区分时再澄清。

加载与 dump 见 [加载器](topics/native-loader.md)，主动终止见 [native 自毁](topics/native-tamper.md)，指令观测见 [轨迹](topics/native-tracing.md)，原函数调用见 [RPC/模拟执行](topics/rpc-emulation.md)。

## 分析步骤

1. 确认目标 so 文件名、路径、架构和来源，选择满足当前问题的分析能力。
2. 查找 JNI 导出函数和 `RegisterNatives` 注册表。
3. 建立 Java 方法到 native 函数的映射。
4. 搜索关键字符串、URL、算法常量、错误码、字段名。
5. 查看交叉引用，定位调用链和数据流。
6. 阅读伪代码，识别参数处理、编码、加密、签名、校验和返回结构。
7. 必要时用 Frida Native Hook 验证入参、返回值和内存数据。

## JNI 与算法线索

仅在目标需要时使用以下判断，不要求运行额外扫描器：

- JNI 映射结合原始类名、完整方法描述符和函数地址判断；只有同名方法、字符串或形似 `JNINativeMethod` 的表时保留为候选。动态注册还需确认注册调用与所属类，不能把表命中直接当成完整绑定关系。
- 没有 `Java_*` 导出或 `RegisterNatives` 字符串，不能排除 JNI 实现；`JNI_OnLoad` 本身也不能证明某个方法已绑定。声明增多或方法体缺失时，按需参照 `package-recon.md` 的 Java2C/JNI 分流，不默认进入 DEX dump 路线。
- 区分文件偏移、ELF 虚拟地址、模块相对偏移和运行时地址；将静态位置用于 Hook 或执行前，确认 ABI、加载基址和重定位关系。
- 将静态函数与运行样本对应时，核对实际加载的 ABI、库副本和版本；同名 `.so` 不保证内容相同，只有加载记录也不能证明目标函数已经执行。
- 常量、查表数据或密码指令命中只能提供算法线索。继续检查引用、输入输出和实际控制流；没有命中也不能排除算法实现。
- 需要复现请求签名或加解密时，按需读取 `algorithm-validation.md`，不强制把自定义变换归为某个标准算法。

native 目标涉及 Dart AOT、IL2CPP 或私有解释器时，按需转入 `flutter-dart.md`、`unity-il2cpp.md` 或 `vm-protection.md`。普通 native 分析无须加载这些专项参考。

## 可选的离线执行

已定位目标函数、但纯静态阅读成本较高，或任务要求脱离设备复现时，可以比较离线执行与现有静态、运行取证路径的成本：

- 依赖较少的局部计算，可考虑 Unicorn 等指令模拟能力；依赖 JNI 或 Android 运行环境时，可考虑 unidbg 等模拟执行环境。工具选择按实际依赖决定，不预装、不固定升级顺序。
- 按需要还原调用约定、内存布局、初始化顺序和跨调用状态。记录时间、随机数、文件、外部函数等依赖的来源；缺失依赖不能用随意补零或固定返回值冒充真实行为。
- 为隔离实验替代某项依赖时，标明替代范围，并与真实输入输出比较。替代后的执行成功、未崩溃或单个输出匹配，不足以证明原实现已完整还原。
- 无法补齐依赖时，保留已确认结果和缺口，改用其他方法补证；模拟失败不能证明真实应用存在同样错误。

方法参考：`owen800q/mobile-reverse-skill@d905f7d` 的 JNI 候选映射与 native 离线执行思路；此处仅保留判断要点，不依赖其脚本或工作流。

## 输出要求

- 当前问题涉及 Java/JNI 关系时，写清 Java 入口和 native 函数之间的对应关系。
- 写清关键字符串、常量、算法或分支的来源。
- 对伪代码结论标注函数地址或函数名。
- 反编译不确定时标注待确认，不把猜测写成结论。
- native 目标与 APK 有明确关系时，将结果回链到 Java 层调用点或真实运行样本；独立 so 分析不强制建立 APK 关联。
- 默认在对话中回答；只有用户要求、正式报告策略启用或 agent 判断需要复用时才创建文档。
