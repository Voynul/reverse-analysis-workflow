# 证据与混淆命名规范

## 可接受证据

- 反编译代码。
- smali 代码。
- 抓包请求和响应。
- Frida Hook 日志。
- mobile-mcp 截图或 UI 操作记录。
- 配置文件。
- 解密后的真实数据。
- `idalib-mcp` 中的 native 函数、字符串、交叉引用和伪代码。

## 声明状态

关键判断使用稳定状态标记，避免把线索升级为事实：

| 状态 | 含义 | 使用要求 |
|---|---|---|
| `Observed` | 工具输出、文件内容或运行结果直接观察到 | 记录证据位置和观察条件 |
| `Inferred` | 多项证据共同支持的解释 | 写明推断链和仍可能存在的替代解释 |
| `Hypothesis` | 有线索但尚未验证 | 给出下一步可区分验证方式 |
| `Refuted` | 已被反例或验证结果否定 | 保留否定证据，避免后续重复探索 |

未命中属于负面证据，只能在工具可用、目标身份正确、索引或采集范围完整且查询方法充分时支持排除结论。

来源方法的验证情况与当前目标结论分开：上游记录、公开文章、工具自测、当前 fixture 回归和真实目标观测各有范围。方法尚未实测仍可作为候选；上游实测也不能直接给当前目标标记 `Observed`。

需要对外分享时生成适当的脱敏副本，保留内部证据的可追溯关系。自动泄露扫描只覆盖其规则和输入，命中需复核，未命中不构成安全证明；不为发布习惯自动删除私有分析中的必要身份。

## 证据分层

| 层级 | 能证明什么 | 不能直接证明什么 |
|---|---|---|
| 静态代码 | 代码存在、分支条件、调用关系 | 运行时一定走到该路径 |
| Hook 日志 | 某次运行的参数、返回值、异常、调用栈 | 所有设备或所有场景都相同 |
| 抓包样本 | 某次请求和响应的真实内容 | 字段一定由某段代码生成 |
| UI 截图 | 当时界面状态 | 底层代码逻辑 |
| native 伪代码 | so 内部处理逻辑 | Java 层一定调用到该函数 |

修改模式还需保存原始产物身份、修改声明、构建日志、签名或安装结果以及运行验证证据。构建成功不能直接证明目标行为已经改变。

## 混淆命名规则

遇到无意义类名、方法名、字段名或变量名时，先理解其功能，再根据分析需要决定是否命名、修改工具内符号或落盘记录。

命名不是每次分析的强制产物。不需要人工继续查看代码时，Agent 可以只在内部推理中理解混淆符号；需要复用、提高可读性或用户明确要求时，再给出可读名称。

命名优先级：

1. `.source` 或调试信息中存在可信名称时优先使用。
2. `toString()`、日志、异常、字符串常量中出现业务名称时优先参考。
3. 根据继承关系、接口、调用方、被调用方和字段用途推断。
4. 不确定时保留原名并说明疑似功能；需要持久化时可使用带 `_TODO` 的暂定名。

## 可选引用格式

需要建立可回查映射时使用：

```text
原名→新名
```

示例：

```text
a.b→RequestSigner.signPayload()
ka.u3→GaConfigManager
```

正式建立语义别名后保留原名，避免无法回查。简单即时分析可以直接使用原始符号并附功能说明，不要求先创建正式别名。

## 可选 rename.md

Agent 根据后续分析是否需要复用，自主决定是否在当前目标的 `.android-reverse/targets/<目标>/` 目录维护 `rename.md`。用户明确要求重命名、提供可读名称或维护命名记录时，用户要求优先。

| 类型 | 原始名称 | 新名称 | 功能说明 | 证据位置 | 状态 |
|---|---|---|---|---|---|
| 类/方法/字段/变量 | 原名 | 新名 | 白话说明 | 类、方法、报告或日志 | 已确认/待确认 |

## 证据索引模板

证据索引不是本技能的强制产物。复杂分析中，如果用户要求、正式报告流程需要，或 Agent 判断后续复用价值较高，可按下表维护：

| 编号 | 结论 | 证据类型 | 证据位置 | 是否已在正文引用 |
|---|---|---|---|---|

证据不足时，不得把推断写成确定结论。不同证据冲突时，先说明冲突，再补静态、Hook、抓包或 native 证据。

中间命名和证据文件默认放在 `.android-reverse/`，但其路径优先级低于用户指定路径、外部项目 plan、`项目规则.md`、上层调用技能和报告技能的文件规划。外部已经规划的文件只记录引用路径，不擅自迁移、复制或重定向。
