# native 指令轨迹与去混淆

需要知道实际执行块、指令或数据变化时使用。可选择局部静态还原、软件 DBI、模拟执行、差分或硬件观测，不规定必须先完整去平坦化。

## 先定义观测

函数调用、基本块、逐指令、寄存器和内存读写回答不同问题。根据目标限定调用边界、模块、线程、输入和窗口；全进程跟踪可能淹没真正差异。

区分控制流平坦化、间接调用、字符串转换和解释器。外层状态分发与 VM bytecode 分发形似，使用状态的来源和数据消费判断，不只看跳转表。

## 采集的健康状态

确认脚本安装、已知控制点、事件生产、消息投递与持久化各环节。排除系统模块可能降低负载或改变生存状况，但不能自动解决零事件。

跟踪本身可能改变代码缓存、时间、线程及资源。对照不跟踪、有限跟踪和具体干预条件；目标进程活着与轨迹可靠是独立判断。

记录实际地址空间、模块版本、线程与调用序号。采样、截断、环形缓冲覆盖、反压及被排除模块形成覆盖缺口，不能把未记录视为未执行。

## 阅读与缩小

- 使用模块相对位置、语义块和数据访问归一化不同运行。ASLR、日志格式和不同初始化路径会制造文本差异。
- 相同输入的重复运行可帮助识别噪声；有区分力的输入变化用于定位相关路径。差分不是自动因果证明。
- 从返回值、内存写入或明确状态反向切片；间接调用、宿主函数与异常路径需要保留。
- 静态状态传播与轨迹可互相校验。根据一次路径还原的 CFG 不代表全部路径，不把可读伪代码当完整恢复。

## 交付

区分原始轨迹、统计、候选 handler、IR 和可执行重写器。用真实输入、状态或独立解析验证关键结论，说明未覆盖部分。

离线差分、符号化及切片实现见 [离线工具](../tools/offline.md)。VM 语义见 [VM](../vm-protection.md)，软件跟踪不可用时可比较 [硬件观测](hardware-tracing.md) 的实际成本和条件。
