# native 完整性与主动终止

用于没有 Java 栈的退出、重建后延迟崩溃或检查响应分析。先解释实际终止路径，不默认把退出 API、库或整个构造器删除。

## 归因

区分异常崩溃、显式 abort/exit、信号、线程终止、ANR、系统回收与平台重启。时间、PID、构建身份和前后台状态与崩溃记录对应，避免把旧事件或另一个进程当成当前结果。

可利用目标参数、日志、调用位置、动态符号、PLT/GOT、反汇编和实际映射互相核对。短小的返回常量 stub 可能属于完全不同的函数，不能凭外形重定向。

静态 ELF 节表可能缺失或被保护，结合程序头与加载关系。错误函数边界、解码未消费完整输入和间接跳转都可能使引用结果不完整。

## 检查与实现可能共存

库既可能承担校验，也可能承担解密、注册和业务计算。删除库或清空 `init_array` 失败，不能证明所有修改都不可行；应追踪判定值、响应位置及其调用约定。

只阻断一个终止机制不代表其他检查已通过。观察到某个检查触发与证明它是最终失败原因，也需要区分。

## 干预的语义

自旋或永久阻塞可能保留进程却冻结线程、持锁和上层调用。正常返回也不自动安全：调用者可能要求特定状态、输出、清理或不可返回的约定。按已确认语义选择处理，而不统一打 `ret`。

可比较原包、相同流程的读写回控制以及目标修改，观察是否实际越过预期路径、是否出现新异常和业务是否继续。保持观测条件可比，不因过程存活就宣布校验已消除。

早期终止不一定有稳定的观察窗口；流式记录关键事件和脚本健康状态，缺失事件保留为缺口。
