# 二进制协议、长连接与消息层次

任务涉及 Protobuf、gRPC、WebSocket、QUIC 或不透明 body 时按需选择章节。网络传输、消息 framing、压缩、编码、密码变换和业务对象是不同层。

## Protobuf 与无 schema 解析

保留 field number、wire type、原始编码、长度范围与重复次数。varint、固定宽度和 length-delimited 只能提供有限类型信息；同一字节可能解释为字符串、bytes、嵌套消息或 packed 数组。

解析时限定深度和长度，检查父子边界和输入消费情况；随机字节也可能形成可解析序列。默认值与未出现字段、字段顺序、重复字段和非规范编码可能影响重编码结果。

回到 APK 中的生成代码、字段编号、解析/写入调用、descriptor 或实际消费者恢复 schema。Lite/V3、混淆和动态构造需要按实际代码处理，不从 getter 名字独立确定全部语义。

在真实配对样本上验证字段解释，必要时再编码比较原字节。字节不一致要区分丢字段、规范化和解释错误；再编码一致仍不能证明字段的业务含义。

## gRPC 与外层 framing

先确认传输和 content type，再识别方法路径、方向、压缩和消息长度。常见 gRPC 消息有压缩标志和大端长度前缀，但输入可能已被工具解帧，不能重复剥离。

一个 body 可含多条消息，响应 trailer 和业务状态也是证据。按真实 schema 和 framing 边界解析，不把整个 body 一次送入 protobuf 解析器后依靠看似合理的输出判断成功。

## QUIC / HTTP/3

代理无记录不等于无网络。结合连接、客户端配置、ALPN 或已有抓包判断实际传输；UDP 路径可能不经过当前 HTTP 代理。

可选择当前环境支持的采集、应用层观测或用户允许的协议对照。未解密的包只能支持可观察元信息，不自动改应用全局配置或假定某个 native 校验是唯一障碍。

## WebSocket 与长连接

把连接建立、鉴权、订阅、心跳、ack、续期、重连、增量与完整同步放在时序中。保留方向、连接身份、序号及 UI/Hook 时间，单帧往往不能独立解释。

外层 envelope 可能含压缩、批量消息和业务 payload；同一字段在不同状态下意义不同。请求响应关联、重复投递及恢复状态分别核对，不只用相近时间配对。

离线重放文件与线上重新发送是不同动作；真实发送需要任务范围内的环境、账户、动作和副作用判断。

## 不透明或加密 body

先检查具体代码中的编码、压缩、framing 与标准算法调用。长度、固定前缀、重复块或差分变化能缩小假设，不能独立证明某个密码模式。

包装变换可能相互抵消，宿主库名称也不能证明算法。取真实输入输出和必要上下文，定位最早差异，按 [算法验证](../algorithm-validation.md) 复现，不盲目搜索固定 key 或算法组合。

## 证据与工具

保留原始消息和解层过程，区分解析结果、候选 schema 与已验证字段。测试 fixture 或官方库对照只证明被测格式，不成为当前业务样本。

操作见 [网络工具](../tools/network.md)、[离线工具](../tools/offline.md)。TLS 信任与 native 证书路径见 [TLS](tls.md)。
