# 原函数调用、RPC 与模拟执行

需要签名、解密或其他函数输出时，可以选择调用目标现有实现、离线模拟或独立还原。三者交付意义不同，根据目标和依赖决定，不要求先完成反编译或完整脱壳。

| 路线 | 合适条件 | 要解释的依赖 |
|---|---|---|
| 进程内原函数/RPC | 正确初始化的进程可用，调用范围明确 | 注入稳定性、ClassLoader、线程、对象实例与隐式状态 |
| 指令级模拟 | 函数边界较小，外部依赖可界定 | ABI、内存、重定位、外部调用、错误和终止条件 |
| Android/JNI 模拟 | 目标依赖 JNI、系统 API 或运行环境 | 初始化、环境补全、库版本和宿主调用语义 |
| 独立实现 | 已知算法或需要可解释、独立部署结果 | 字节语义、真实样本和跨条件验证 |

## 界定一次调用

确认入口、完整签名、参数编码、输出内存、异常及清理。初始化可能发生在 Application、JNI_OnLoad、首次调用、账户会话或远程配置之后；运行成功一次不代表无状态。

记录设备值、时间、随机数、文件、网络及对象生命周期。实验替代值可以帮助隔离问题，但不能悄悄作为算法常量。重复调用还要检查缓存、序号和内存副作用。

RPC 调用业务方法可能发请求或写数据，执行前确认当前任务允许的动作与账户范围。需要批量调用时明确并发、超时、会话失效和重试是否会重复业务动作。

## 失败处理

模拟崩溃先查地址空间、调用约定、初始化和缺失依赖，不随意映射零页或为所有未实现函数返回成功。输入变化后的差异可用于缩小依赖，但要保留失败样本。

RPC 无输出先核对脚本与消息链路、进程和调用线程；不能把超时解释为算法拒绝。工具构建错误与目标逻辑错误分开。

## 交付与验证

说明交付的是独立算法、原二进制的离线执行器还是依赖原进程的服务。固定一个设备状态或某次初始化值只能支持对应条件。

将真实输入输出按 `../algorithm-validation.md` 验证。工具接口、监听和 session 处理见 [Frida](../tools/frida.md) 与 [专项工具](../tools/specialists.md)。
