# 设备与环境诊断经验

在环境影响取证或验收时读取，不是每次启动的全量检查表。记录当前任务相关事实，变化后再重新核对。

## 身份与存活

确认设备、目标包/版本、PID、前台、进程状态和实际加载 ABI。root 状态、模拟器、翻译层、可调试标志与实际权限分别核对，工具存在不等于可操作目标。

进程暂停、不可运行状态或反复被平台启动可能造成 attach 卡住和 PID 漂移。结合进程与系统事件解释，不以一次连接错误判定反分析。

## 日志与界面

用时间、PID、构建身份和日志来源对齐样本；进程重启会改变 PID，旧缓冲还可能保留前一版本的错误。事件、应用、系统和框架日志的可见范围不同。

`logcat` 沉默不证明没有运行，截图也可能是安装器、权限对话框或旧任务。核对前台应用与目标路径，再将界面和底层证据关联。

## Shell、网络与状态

区分宿主 Shell、ADB 参数、设备 Shell 和提权方式；参数被提前展开时，命令可能成功却作用于错误位置。优先明确参数与有限命令，不依赖多层拼接。

设备时钟、DNS、代理、转发、系统/用户 CA 和已有会话可影响网络。检查与问题相关的设置，保留用户原有配置，不为排障自动清空或重置环境。

若任务需要恢复或交接，记录已确认环境条件和改变过的设置；不要把一台设备的限制升级为所有动态工具或平台的限制。

操作接口见 [设备工具](../tools/device.md)，Hook 排错见 [反分析](anti-analysis.md)。
