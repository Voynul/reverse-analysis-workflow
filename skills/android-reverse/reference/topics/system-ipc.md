# 系统 IPC 与平台边界

用于应用向系统请求什么、谁提供响应、哪些条件来自平台等问题。进程内代码、系统服务、网络和证明链可以共同决定行为，不能只读一个返回值就确定所有权。

## Binder / AIDL

从服务获取、代理接口、方法参数和结果消费者定位。事务编号、接口 token、Parcel 布局及权限检查按目标系统版本和实现确认，不能从另一版本复制常量。

区分应用自行提供的参数、Binder 调用身份与服务端检查。能发送某个事务不代表具有相应权限，错误响应也可能来自解包、版本或服务不可用。

观测限定目标服务和数据范围，明确记录调用方向、对象、时间及身份。高频全局 Hook 或 system_server 级操作不属于普通应用观察的隐含步骤。

## Intent 与组件入口

结合 Manifest、运行检查、导出状态、权限、URI、extra 和调用链分析。静态声明与实际可到达性分开；入口被删除也不等于所有内部调用路径消失。

验证动作需要判断是否启动业务、写数据、打开外部应用或涉及账户。只读结构审计不默认执行所有入口。

## WebView / JS bridge

核对页面来源、加载流程、接口暴露、参数序列化和调用身份。页面文本、远程 H5、assets 脚本、注入脚本及 native bridge 的作用不同。

需要逆向脚本时转到 [AST](js-ast.md)、[JSVMP](jsvmp.md) 或 [React Native](../react-native-hermes.md)，不把所有 JS 环境混同。桥接接口存在与某页面真正能够调用，也需分别验证。

## SELinux 与设备证明

权限、uid、域、策略及 `avc: denied` 的主体和对象共同解释操作失败。不要从一条拒绝日志推导目标在主动检测，也不默认放宽策略。

Keystore、硬件安全环境、证明证书、nonce、应用身份及远程验证组成可能的信任链。客户端显示值或局部 Hook 不能直接证明远端接受了证明，区分取得、解析、校验与业务授权。

具体接口和数据布局以目标版本和可取得证据为准。工具操作见 [设备](../tools/device.md) 与 [Frida](../tools/frida.md)，平台以外的业务权限见 [账户与限制](accounts-limits.md)。
