# JSVMP 与 JS 解释器恢复

当目标参数由应用控制的 JavaScript 解释私有载荷产生时使用。与 native VM 可以共享数据流方法，但 JavaScript 的类型、求值顺序、闭包和异常语义需要单独处理。

## 识别与工作目标

寻找载荷传入、opcode 读取、PC 更新、状态存储和分发执行之间的关系。巨大字符串、大 switch 或某个请求参数名单独出现都不构成 JSVMP 结论。

按任务可选择直接调用原模块、恢复局部状态与 handler、或建立最小可验证的重执行。需要解释算法时可以深入阅读，不要求所有任务先做黑盒调用；只需结果时也不强迫恢复完整 ISA。

## 载荷与宿主环境

- 从加载器实际代码推导字节链：可能是 hex、Base64、压缩、varint、ZigZag 或自定义编码。先验证链条及边界，不能把某种已知链用于所有载荷。
- 依赖数组可能同时提供导入对象和环境探测。区分显式参数、全局对象、设备状态、时间、随机数、cookie、持久化数据及异步回调。
- 补环境要记录哪些值来自真实运行、哪些是实验替代。输出可计算不证明服务端接受，也不证明任意设备环境等价。
- 存在多个 executor、严格/非严格版本或嵌套 VM 时，确认目标实际走的入口、共享状态和异常返回，不能凭名字相似删掉一份。

## 栈机与寄存器机

栈机关注 push/pop、栈指针、调用帧及结果所在位置；寄存器机关注索引来自载荷还是状态表、立即数与寄存器操作数的区分。分发值也可能经过算术变换，不能把 opcode 字节范围当成 switch 的 case 范围。

识别 handler 时记录操作数获取顺序、长度、PC 变化、状态读写及宿主调用。分支或变参调用可能采用不同长度；未理解的部分保持未知，不能用猜测维持连续反汇编。

## JS 特有的语义陷阱

| 项目 | 恢复时要保持的内容 |
|---|---|
| 带副作用的赋值表达式 | 左侧引用的求值与右侧求值顺序；不能照另一语言的执行顺序拆开 |
| `PC += code[++PC]` 一类复合表达式 | 原左值读取时机，不能直接改写成看似等价的两句 |
| `this` 与严格模式 | 调用形式、显式绑定和默认全局绑定的差别 |
| 闭包和嵌套调用 | 每次调用的 PC、词法环境、寄存器/栈帧和异常处理状态 |
| 正常返回 `undefined` | 返回事件与返回值分开，不能用值是否为 `undefined` 判断是否退出 |
| 数值与位运算 | JS Number、32 位位运算、BigInt、字符串强制转换及比较规则 |

## 从轨迹到可读表示

可按目标 handler 或数据写入提取操作，记录寄存器、立即数、环境访问与分支。AST 变换、反汇编、IR 和重解释器是不同产物，分别说明恢复到了哪一层。

常量折叠需要稳定输入和副作用判断；单条轨迹中的环境值被固化后，得到的可能只是某次调用或某条路径。保留载荷、常量、输出位置及状态来源，跨输入比较后再扩大适用范围。

运行实际取得的程序片段，对照输出、异常和必要的中间状态。正常退出不是唯一验收条件，opcode 表完整也不代表操作数与调用约定正确。
