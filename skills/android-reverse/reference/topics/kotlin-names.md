# Kotlin 名称与结构恢复

混淆名称不妨碍根据注解、调试信息和调用关系提出语义别名。恢复辅助阅读，不要求批量改写符号或生成命名文件。

## 候选来源

- 调试 metadata 中的声明类、文件和方法可提供线索；协程、lambda 和内联生成类需要区分外部声明与当前类。
- Kotlin metadata 的字符串和类型描述符可能保留名称，也可能已被重写、剥离或混淆。不能假设所有 R8 构建都保留原名。
- `.source`、`toString()`、序列化字段与反编译器的 renamed 注释可辅助，但不与原始 debug 信息等同。
- 同一文件可包含多个描述符，出现的第一个字符串可能属于接口、参数或引用类型；候选映射需结合当前声明验证。

## 使用

先将候选与继承、类型、字段、调用点和运行名称对应。不能可靠确认时保留原名附疑似功能，不用名称恢复工具的输出替代功能证据。

查找同包邻居可能帮助推断子系统，但文件路径、重新打包命名和同名类会影响查询。原始名与阅读别名同时保留，以便 Hook 使用运行名称。

是否更新工具内符号、落盘映射或维护 `rename.md` 由任务和复用价值决定，不能因脚本能输出地图就自动重命名全项目。

已迁入的辅助解析器见 [离线工具](../tools/offline.md)；结果为候选，嵌入样本测试通过不能证明任意 Kotlin metadata 版本都支持。
