# 运行数据、缓存与回写

目标状态位于 SharedPreferences、DataStore、MMKV、SQLite、文件或其他持久化介质时使用。读取到某值与证明它决定行为是不同结论。

## 从消费者和写入者确认格式

| 介质 | 检查重点 |
|---|---|
| SharedPreferences/XML | 类型、默认值、异步写入及实际文件路径 |
| AndroidX DataStore | 实际 schema、类型分支、序列化与 Flow/缓存消费者 |
| MMKV | 对应库格式、伴随状态、校验与多进程访问，不当普通 XML 修改 |
| SQLite/Room | schema、事务、WAL、游标和业务约束，单独复制主文件可能不完整 |
| JSON/protobuf/自定义 blob | framing、编码、压缩与加密分层，以及真正的解析调用 |

不可读字符串可以先做有依据的编码/压缩判断；结构候选和高可打印性不是解密成功证明。使用真实输入，再编码时确认与目标格式一致。

## 状态来源与持久性

值被改回不一定是写入失败。可比较进程内缓存、启动默认写入、远程同步、定时任务及多个进程；离线/在线和重启对照只在能区分当前假设时使用。

缺少键可能触发默认值；新增键也可能被忽略。先查读取方式，不依据界面名猜 key 或类型。时间戳、token 和计数器还可能由服务端或其他介质约束。

## 修改实验

只有任务允许时才改变数据。保留原始证据与明确的实验副本，理解当前进程是否仍持有缓存或写回任务；停进程本身也会改变运行条件。

核对所有权、uid、SELinux 上下文、序列化边界及必要伴随文件。权限、不可变属性或阻断刷新可能损害正常写入，不作为统一的持续性方案。

设备上的文件编辑、代理或 Hook 不随 APK 自动分发。需要干净安装仍生效时，结合初始化和业务决策设计可交付方案，再验证用户要求的条件。

## 输出

记录数据身份、实际消费者、写入来源、取得条件及验证范围。敏感数据不直接放入普通日志；对外脱敏副本不替换原始内部证据。

工具见 [离线解析](../tools/offline.md) 与 [设备操作](../tools/device.md)，业务权限归属见 [账户与限制](accounts-limits.md)。
