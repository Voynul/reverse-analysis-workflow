# JavaScript AST 去混淆经验

适用于 WebView、内嵌引擎、热更新或小程序载荷中的结构混淆。压缩、字符串表、控制流平坦化和 JSVMP 是不同问题，可分别处理，不要求先完成全文件美化。

## 从需要回答的问题选择变换

- 保存原始输入和可取得的运行输出，标明脚本、加载上下文和版本。格式化只能改善阅读，不证明逻辑已恢复。
- 字符串表、旋转 IIFE、解码器别名、代理函数和状态分发可提供候选。文件名、参数名或检测器评分不是结构证据。
- 候选变换包括字面量规范化、字符串表解析、稳定别名替换、纯表达式折叠、分发器内联、可证明的分支简化及名称整理。按依赖关系和目标调整顺序，不套固定 pass 清单。
- 大 VM 文件中，全面内联或常量传播可能使 AST 急剧增长；可缩小到加载器、目标函数或少数 handler，阅读与运行验证可以交替进行。

## 保持语义的条件

改写前理解绑定的作用域、可变性和引用。相同标识符在不同闭包中可能不是同一对象，名字相同也不代表可合并。

| 风险 | 判断重点 |
|---|---|
| 表项、别名或函数返回值可能变化 | 检查写入、别名逃逸和闭包依赖，不只看一次调用 |
| getter、setter、Proxy 或动态属性 | 属性读取本身可能执行代码，不能按普通字典折叠 |
| `this`、严格模式及调用形式 | 方法调用改成普通函数可能改变绑定 |
| 逗号、逻辑短路、复合赋值 | 保持求值顺序、短路与副作用，不能只比较最终表达式文本 |
| 环境与异步依赖 | 时间、随机、DOM、计时器及 Promise 状态可能参与结果 |

需要执行解码器时优先隔离最小初始化片段，限制文件、进程、网络与执行时长；不要把 Node REPL 或简单 VM 上下文当成可靠的安全沙箱，也不默认执行整个下载脚本。

## 验证变换

每批有实质变化的输出重新解析，并对相关真实输入比较返回值、异常和可观察副作用。AST 可解析或混淆特征减少不等于语义一致。

保留变换作用范围和未处理区域。没有匹配可正常结束；结构不符合时停止该变换，其他分析方法仍可继续。目标已可读时不为降低残留指标无限美化。

JSVMP 的执行与状态恢复见 [JSVMP](jsvmp.md)。工具选择见 [离线工具](../tools/offline.md)；已迁入的 JS 分类器只提供启发式线索，未提供完整 AST 重写实现。
