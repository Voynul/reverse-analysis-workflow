# 原生远程调试与映射问题

任务需要断点、线程、寄存器或内存状态，且当前环境有合适无头接口时使用。GUI 调试步骤不是默认路线，也不要求普通静态分析先附加进程。

## 准备可解释的连接

核对实际进程 ABI、服务器/协议、权限、端口和目标 PID。设备宣称架构与进程实际执行的库可能不同，翻译层会影响调试。

等待调试器、应用启动暂停、JDWP 和 native 附加具有不同阶段；进程暂停时不会自行加载目标模块。根据实际接口安排连接、恢复和断点，不复制某个 UI 的点击顺序。

## 断点不绑定

检查模块是否已经加载、工具地址空间、ASLR、代码页、符号来源及运行库副本。未解压 native 库可能直接从 APK 映射，路径和文件偏移与提取文件不同。

JIT、匿名映射、运行时生成代码或私有加载器不一定有普通文件符号。软件断点、硬件断点和执行跟踪也可能被不同条件限制。

先用已知可到达的点核对通道，再解释目标未命中。连接失败、断点未绑定、断点未执行与代码不存在分别记录。

## 使用与影响

暂停改变时序、锁、watchdog 和超时；调试器状态也可被目标观察。需要对照未暂停运行的行为，不称调试过程完全透明。

只连接任务允许的设备和进程，必要转发优先本地；结束时释放本任务连接，不关闭其他人的服务。与 [反分析](anti-analysis.md)、[加载器](native-loader.md) 和 [硬件观测](hardware-tracing.md) 配合。
