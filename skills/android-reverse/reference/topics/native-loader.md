# 自定义加载器、linker 与 SO dump

适用于加载路径、私有容器、解密映射、重定位或 dump 与磁盘文件不一致。这里描述判断方法，不提供固定 `soinfo` 偏移或统一修复补丁。

## 谁负责检查，谁提供实现

从 Java/JNI 调用、`DT_NEEDED`、加载字符串、注册关系和实际映射确定库的作用。名字、SONAME、磁盘文件和内存镜像不一定对应同一对象。

校验库也可能提供解密和业务实现。保留它与删除它都失败时，查明检查输入、判定与实现之间的依赖，而不是反复增删整个库。必要时分析局部调用或载荷关联，不自动改写完整性判断。

`DT_NEEDED` 表示加载依赖，不能自动证明某个 JNI 初始化或业务函数已执行。构造器、JNI_OnLoad 和真实 Java 入口分别追踪。

## 地址与重定位

- 以程序段、实际加载偏移和映射证据区分文件偏移、ELF 虚拟地址、load bias 与运行时地址；不能默认减一个映射起点就得到文件位置。
- 解析动态表和重定位类型，区分调用库地址与定义符号所在库地址。跳板、GOT/PLT、间接解析和版本绑定可改变实际目标。
- 表中的零值可能等待重定位或初始化，非指针值也可能是编码；逐项核对，不直接判加密。
- 节表缺失或伪造时优先核对加载所需程序头和映射，工具仍可能因缺元信息降低可读性。
- 系统 `soinfo` 和私有结构随平台、版本与厂商变化；复用布局前用相同实现或实际字段访问验证。

## dump 时机与形态

加载、解密、重定位、构造器、注册及首次使用之间可能存在不同可读窗口。根据目标实际消费指令或数据的时刻取证，不能统一选择某个入口或第几份映射。

保存映射范围、权限、来源路径、基址、取得时间及未读区域；空洞和补零在结果中标明。内存镜像不是天然可加载 ELF，切勿直接覆盖原文件。

需要工具消费时，先判断它要求原文件布局还是内存布局，再单独生成修复/重定位副本。不能把所有段的 `p_offset` 设成 `p_vaddr` 当通用规则；修复成功也不证明重新执行正确。

## 校验

用可识别字符串、导出/注册点、局部函数和已知数据互相核对。选择了错误库副本、ABI 或旧缓存时，静态修改可以完全正确而运行无影响。
