# 广告、弹窗与远程 UI 配置

用于用户要求解释或修改广告、启动页、推荐、公告、tab 等行为。先从实际功能判断，不把所有营销 UI 都归为某个 SDK。

## 找到控制路径

可从 SDK 初始化与 wrapper、展示回调、页面数据、远程配置字段和 UI 构造追踪。区分请求、预加载、展示、关闭、奖励和后续业务完成；同名广告位也可能存在多个路径。

本地默认、磁盘缓存和远程响应可能依次覆盖。记录读取时机、配置版本及渲染消费者，避免静态改了一个默认值却仍被运行配置覆盖。

数据类保留的字段、字符串和反序列化路径可用于定位，但字段名不能独立证明归属。Flutter、RN、WebView 与 Android 壳可能分别渲染不同部分。

## 修改方案按影响选择

- 明确是隐藏视觉、停止请求、移除 SDK、保留奖励回调还是只处理某一入口；这些结果不同。
- 可选专用决策、展示 wrapper、业务配置或解析位置，核对其他消费者。共享 helper 的影响面可能跨广告和核心业务。
- 单纯破坏 URL、接口或 JSON 结构可能触发错误流程、阻塞初始化或页面加载。需要改变请求时，连同异常和回调行为一起验证。
- 让展示函数不再返回、取消完成回调或伪造奖励状态都可能改变上层业务，应根据用户范围和真实调用语义决定。

## 持续性与证据

按目标比较冷/热启动、在线/离线、已有/新配置与缓存条件，不要求每次任务全部执行。资源热更新、其他页面入口和第二层配置可能重新启用目标。

截图只证明当时 UI；请求消失、方法未命中和后台初始化也各有证据边界。功能变化、相关回归和未修改范围分开说明。

修改验收见 [验收](../patch-and-verify.md)，缓存见 [运行数据](runtime-data.md)，服务端权限归属见 [账户与限制](accounts-limits.md)。
