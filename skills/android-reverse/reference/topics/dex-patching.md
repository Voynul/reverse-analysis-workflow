# DEX 与 smali 修改方法

只在已授权修改或故障诊断时使用。技术选择取决于能否表达目标、无关差异和可验证性，不规定所有任务统一使用原位修改或方法重写。

## 选择变更层

| 技术 | 适用条件 | 主要约束 |
|---|---|---|
| 等长原位修改 | 变更可表达在已有编码空间 | 指令边界、操作数、控制流、引用和完整性 |
| 方法级重写 | 新指令、寄存器或控制流需要重建 | 表项、try/catch、调试与共享数据可能重新布局 |
| smali/完整重建 | 变更跨方法、Manifest 或资源 | 汇编、资源重编译和运行时结构差异 |
| 原归档内替换目标 DEX | DEX 已可靠生成且无需改变其他条目 | 压缩、对齐、签名及集合依赖 |

选择专用业务控制点，检查上游与消费者；公共序列化、装箱、日志或 SDK helper 的影响范围通常大于某个功能。

## 定位与原字节断言

从类、方法描述符和 code item 定位，再解码指令；源码 `.line` 不是唯一字节偏移。索引 delta、指令宽度和 switch/array payload 要按真实格式处理，解码中断后的偏移不可信。

替换前确认输入身份、原字节、目标唯一性和分支方向。文本补丁匹配空白、CRLF、完整指令名与描述符；零命中或多命中要解释，不能无声选择第一处。

## 字符串、寄存器与分支

- 相同字节长度不保证 DEX 字符串编码、字符计数、引用和字符串表排序仍合法。变长或跨索引变化可选择可靠重写器，不手工猜偏移。
- 固定长度修改也会改变行为。删除或改变条件时检查两条路径，而不统一选择 nop 或 goto。
- 保持结果生产指令与 `move-result*` 的合法关系，并检查新进入边、寄存器类型、宽寄存器、异常处理与返回约定。
- 重写可能重排常量池和调试数据；类表一致不能证明 code item 及执行语义一致。
- DEX 头部完整性通过可靠实现更新并验证，不能只修 checksum 后宣称字节码正确。

## 验证实际产物

从修改声明中的每个目标直接核对最终方法/指令，而不从长度变化列表推导全部目标。比较声明外变化时区分索引重排噪声与语义变化；等长替换不应漏审。

匹配片段被新内容包含时，旧片段仍存在不一定表示失败；验证新增的唯一条件和实际指令。补丁输出已成功但运行未变时，核对安装构建和加载副本。

局部解析器、邻接扫描、问题数量或 class-set diff 都不能代替运行时验证。验证规模由交付物和修改风险决定；完整流程见 [修改验收](../patch-and-verify.md)，操作见 [APK 工具](../tools/apk.md)。
