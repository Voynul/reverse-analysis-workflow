# 设备侧分析与工具协作

目标已安装在设备、用户选择设备侧操作或主机工具不合适时，可以利用 MT/APK MCP、Termux、设备侧解析或框架接口。设备侧并不天然比主机准确或低成本。

## 选择位置

考虑文件取得、格式支持、可重复性、输入输出量和版本记录。已经有主机 MCP 或现成产物时，无须为很小的任务迁移整套环境。

设备侧工具可提供 Manifest、DEX、资源、签名和文件操作，也可能主要依赖人工 UI。以当前实际暴露接口确认能力，不从产品名称推断完整 MCP 表面。

## 取证与修改

核对操作的是 APK、已安装目录、动态载荷还是应用数据。提取的单个文件可能不包含 split 或热更新所需内容。

明确设备权限、用户目录、任务输出与原文件。编辑、重建、重签和安装各有状态；管理器报告保存成功不证明安装的是该产物。

原应用数据、模块或框架环境可能改变表现，不能把只在当前设备出现的结果说成自包含 APK。手工动作需要保留足以复现的步骤和边界，不要求普通自动任务转为 GUI。

接口见 [设备工具](../tools/device.md)，集合与归档分别见 [split](split-packages.md) 和 [修改验收](../patch-and-verify.md)。
