# TLS、证书链与功能局部网络故障

用于 HTTPS 失败、某个功能联网失败或代理看不到明文等现象。传输、证书链、信任策略、pinning、协议及业务拒绝分别判断，不统一关闭验证。

## 取得真实失败位置

对应域名、时间、设备时钟、客户端实现、错误类别及调用点；原包在同环境的表现提供基线。一个页面能联网不证明另一个域名、SDK 或 native 栈使用同一信任路径。

在任务允许范围内对照证书链、有效期、主机名、重定向、系统信任与中间证书。另一台主机上的成功只支持该环境，不能直接覆盖设备上的失败。

## 信任路径

- 平台 TLS、应用自定义 TrustManager、OkHttp、WebView、Flutter/native 网络库可能分别验证。
- 安装 CA 不保证所有应用栈接受；系统策略、用户证书策略与客户端 pinning 不是同一层。
- 代理或 Hook 引入的证书、ALPN、HTTP 版本、协议重试与网络路径变化也可能影响结果。
- 看到校验函数、某个字符串或一个失败返回值不等于它是根因；追踪到请求是否实际经过该路径。

## 选择验证方式

可比较原环境、受控代理与具体的局部观测；用户要求采集明文时再判断是否需要授权范围内的验证路径调整。全局宽松验证可能掩盖证书或客户端错误，不作为默认修复。

原包也失败、时钟不正确、服务端链异常、握手未完成或 QUIC 未经过 HTTP 代理时，先保留这些候选。应用业务错误码与 TLS 握手失败分开记录。

记录明文样本的取得条件；主动绕过后的请求不能代替原环境结果。具体接口操作见 [网络工具](../tools/network.md)，协议路径见 [协议](protocols.md)。
