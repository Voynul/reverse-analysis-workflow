# 可复用案例与经验回写

以下整理来源项目的五类案例模式，不将它们写成本技能实测，也不复制目标数据、地址、设备配置或耗时作为新目标常量。复杂任务有复用价值时可保存案例，普通回答无须生成文件。

## 多运行时与保护层共存

现象：界面正常或进程不断重启，分析却长期停留在 Java 壳。

可复用经验：先对应运行时、真实业务产物和系统生命周期，再区分加载器、检测响应和业务层。看到某框架存在不代表当前功能都归它，也不因 PID 漂移就认定某个检测器在杀进程。

## spawn 挂起与零事件

现象：工具连接看似正常，观察脚本一直没有业务日志。

可复用经验：暂停进程尚未加载目标模块、脚本未安装、事件未投递、版本/API 错误和目标未经过该路径都有可能。用可观察的控制点拆分链路；排除模块后进程存活也不能直接证明事件覆盖已恢复。

## 日志通道异常与模块未运行

现象：应用侧看不到模块日志，因而推导模块没有执行。

可复用经验：平台、框架、应用和文件记录可能具有不同覆盖。将模块加载、安装回调、目标调用和日志健康分别核对；日志缺失不是业务不存在。

## 等长修改与对照构建

现象：文件大小、类表和签名都合理，实际修改是否生效仍不明确。

可复用经验：从声明目标回查最终指令，对照相同工具链产生的无业务修改构建，分开验证修改落点、格式合法、安装身份和业务效果。

## 自动检查遗漏与人工发现

现象：扫描器没有报告，但后续阅读发现未处理身份、凭据或其他问题。

可复用经验：明确扫描对象、规则和输出范围，使用真实的反例更新覆盖。未命中不升级为安全结论；为对外材料生成脱敏副本，避免删除内部分析所需证据。

## 可选案例结构

需要保存时记录：目标身份的适当引用、原始问题、条件、实际执行与输出、已否定路径、关键证据、结论范围和下一次如何识别。来源经验、当前观察、推断与尚未验证内容分别标明。

案例不成为无条件操作规则。确认新目标具有相同机制后再复用，必要时修改原假设。相关专题见 [故障目录](failure-catalog.md) 和 [证据](../evidence-and-renaming.md)。
