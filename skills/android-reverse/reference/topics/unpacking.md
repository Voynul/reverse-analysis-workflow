# 加固、抽取恢复与载荷质量

用于目标实现被包装、解密、按需恢复或动态加载的线索。先围绕需要回答的方法判断，不要求分析任何功能前都完整脱壳。

## 区分相邻形态

| 观察 | 候选 | 补证 |
|---|---|---|
| 入口很小且加载另一个载荷 | 包装或整体加载 | Application/组件、ClassLoader、资源与加载调用 |
| 方法可列出但正文是骨架 | 抽取、按需恢复或其他转换 | 调用前后同一方法的代码、恢复函数与载荷关系 |
| 方法变为 native | JNI 下沉、Java2C 或解释器入口 | 注册、对应 `.so` 实现，不能默认寻找解密 DEX |
| 可解析但反汇编异常 | 格式/解码器错误、quickening、私有编码或损坏 | 独立解析与版本、指令边界、真实执行关系 |

壳名称、体积、native 比例和简单 stub 比例只能支持候选。正常构造器、接口、异常 stub 或解码器漏支持都可能影响统计。

## 取得需要的代码

已有合法取得的缓存、加载产物或构建文件时可以先利用。运行取证可从文件加载、DexFile/类加载、恢复时机或目标调用进入，按任务范围限定模块和窗口。

扫描内存只能找到当时存在的内容；按需恢复的实现可能尚未调用。主动调用也可能触发构造器、网络、数据修改或异常，不默认反射遍历所有方法。

Frida、ART 插桩、外部进程读取或其他路径各有版本和权限依赖；选择实际可用的一条，失败不能直接证明目标没有载荷。

## 解析与去重

- 记录来源、时间、进程、模块/映射及范围，不以文件名或相同大小判断重复；需要去重时使用内容哈希。
- 内存映射可能包含页对齐填充。按已核对的格式长度识别镜像，保留原始取得物，修剪结果另存。
- 验证头、范围、索引、类/方法及关键实现，并在重要结论处交叉检查。校验字段正确不证明骨架已恢复。
- 多份 dump 可能各含部分不同方法，不能只用某个评分最高者替代其他候选。合并 code item 前理解长度、try/catch、调试及引用关系。
- 类数量、可读字符串或构建成功都不等于关键路径已恢复；说明实际覆盖的方法与缺口。

## 后续决策

保护加载器可能同时执行业务初始化，不能默认删除库、资源或 `appComponentFactory`。需要可安装脱壳产物时，先确认真实入口和初始化依赖，再按 [修改验收](../patch-and-verify.md) 建立对照。

只需要局部输出时可用 [RPC/模拟执行](rpc-emulation.md)，发现解释器证据时转到 [VM](../vm-protection.md)，加载器内部见 [native 加载](native-loader.md)。
