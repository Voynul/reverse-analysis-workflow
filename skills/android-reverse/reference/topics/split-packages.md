# Split APK、App Bundle 与安装集合

一个应用身份可由 base、ABI/语言/密度 split、动态功能模块和更新产物共同组成。容器后缀不决定是否可直接安装；先取得集合清单和各成员身份。

## 分析输入

检查包名、版本、split 关系、模块、ABI、资源、DEX、native 库及签名。缺少某个配置成员时，解析工具仍可能成功但任务代码或资源不完整。

用户提供 AAB、APKS、APKM、XAPK 或设备安装集合时，确认分析目的与最终交付形式。不要仅处理 `base.apk` 后宣称整个目标已覆盖。

## 集合安装与重签

可保持完整集合，按目标设备选择所需成员，并使用支持集合的安装流程。成员签名及版本必须满足平台要求；签名单独通过不等于集合可安装或启动。

重新签名可能影响升级、共享身份、配置获取及证书派生输入。不要通过自动卸载原应用掩盖签名或版本问题，数据影响按用户授权处理。

## 合并不是追加归档

仅含部分代码或 native 的配置 split 与带独立资源表、Manifest 或动态功能依赖的集合有不同复杂度。将条目复制到 base 不能自动解决资源 ID、模块路径与装载关系。

任务允许时可比较完整集合安装、正式打包能力生成设备匹配集合或经过验证的合并。已有失败应解释具体依赖，不以工具拒绝合并推导整个任务不可行。

## 验证

从最终安装身份、实际模块及目标行为确认结果。安装成功、所有成员已签名、指定 ABI 被使用和功能通过分别记录；本机有效不自动覆盖其他 ABI、语言、密度或动态模块条件。
