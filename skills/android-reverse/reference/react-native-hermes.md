# React Native / Hermes 定位

## 何时读取

目标功能可能位于 React Native 的 JS bundle 或 Hermes 字节码时使用。以下是定位思路，按证据选择，不要求解码字节码、Hook 或读取设备私有目录。

## 确认真正的业务产物

- RN 加载代码、`libhermes.so`、React Native 相关库和 bundle 名称可作为线索；单个库或文件名不能证明当前功能实际使用该引擎。
- 优先检查已有 APK、用户提供的 bundle 和已取得的加载记录。根据文件内容区分文本 JavaScript、Hermes 字节码或其他格式，不单凭 `.bundle`、`.jsbundle`、`.hbc` 等后缀判断。
- 如果存在与目标功能及版本对应的可读 JS，可以直接追踪请求和业务逻辑，无须为此先反编译 Hermes。没有文本副本时，不假设其他目录一定存在源码。
- 热更新、多业务 bundle 和不同缓存版本可能并存。将候选文件与实际加载来源、应用版本及触发功能对应；设备数据提取仅限任务已授权范围，不遍历无关应用数据。

## 从已有证据缩小范围

- 使用 URL、字段名、业务方法、错误文本或 UI 线索定位模块和请求构造函数；关注序列化前后的对象及 JS/native 交接位置。
- 必要时追踪签名、token、设备字段来自 JS、native 模块还是远程响应，避免仅凭 Java 桥接层推断业务实现。
- 后续请求可能依赖首个响应产生的 session、游标或一次性字段。根据真实请求顺序确认依赖，不套用某个应用的接口名称、目录或调用顺序。
- 本地 bundle 已足够回答问题时，可以结束静态分析；只有证据缺口影响结论时再选择运行观测。

## 只有 Hermes 字节码时

先读取实际字节码头及可取得的版本信息，再选择兼容的无头解析或反汇编能力；不假设某个工具支持所有版本。文本化结果只显示字符串、模块或调用关系时，不描述为完整源码。

工具不兼容时可以记录缺口，改用加载入口、JS/native 边界或任务范围内的运行证据。解析失败不能证明功能不存在，也不要求为继续任务自动安装工具。

## 证据与输出

结论引用具体 bundle、版本或哈希等可取得的身份信息，以及模块、函数、字符串位置或字节码偏移。涉及请求签名或算法复现时，再按需读取 `algorithm-validation.md`。
