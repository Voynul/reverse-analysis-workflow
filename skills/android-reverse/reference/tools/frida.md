# Frida MCP / CLI / RPC 操作

首次使用本分支时确认设备、进程、客户端与服务端兼容性；连接及设备未变化时复用结果。服务未运行且任务允许启动时使用实际启动能力，不假设固定 server 文件名、root 命令、Conda 环境或安装目录。

## 选择与调用

- 从当前工具 schema 确认列进程、spawn、attach、加载脚本、获取消息和关闭 session 的真实接口，不猜测别名。
- 使用 CLI 时通过当前 Shell 的命令发现、明确配置路径或已检查的适配器定位。不要因不在 PATH 就认定未安装，也不扫描整台机器作为默认步骤。
- spawn 暂停期尚未必加载目标库。根据目标时机安排恢复、加载观察和 Hook；不要等待一个暂停进程自行完成初始化。
- Java 重载使用完整参数类型保存 overload handle，并通过它调用原实现。类和方法使用运行时名称，阅读别名不能代替原名。
- 类或符号查询失败时核对 ClassLoader、加载时机、架构、bridge 可用性和当前版本 API。不能把脚本 API 错误当成业务结果。
- 等到脚本明确报告已安装或初始化成功，再解释业务日志；同时检查消息是否实际到达。

## 会话与 RPC

RPC 只暴露任务需要的函数，明确初始化、参数/返回转换、异常、超时和会话状态。确认调用是否执行网络、写数据或其他业务动作；不要将原函数调用描述为独立重写。

不默认向外网开放 RPC 监听。会话结束只释放本任务拥有的脚本与连接；不要关闭其他任务依赖的共享服务。

## 输出与影响

记录足以区分样本的时间、线程和调用边界。大对象按问题限定采集，不将密钥、token 或无关明文直接写入普通日志。

指令跟踪和 Hook 可能改变目标表现；分别记录无注入、仅观察和主动干预条件。方法参照 `../dynamic-hook.md` 与 `../topics/anti-analysis.md`，不要求两者使用固定脚本。
