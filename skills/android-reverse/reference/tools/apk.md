# Apktool / 归档 / 对齐 / 签名工具操作

只在修改、重建或相应故障诊断分支读取。选择工具后，记录本任务实际使用的版本、输入、输出和关键配置，不要求每一步重复健康检查。

## Apktool

- 使用 MCP 时按实际 schema 调用 `decode_apk`、`build_apk` 或项目操作；服务可能限制工作区，输出路径以配置和返回值为准。
- `no_src=true` 对应 `-s/--no-src`，保留 DEX；`no_res=true` 对应 `-r/--no-res`，保留资源表。根据修改目标选择，不能将 `-s` 解释为不解码资源。
- 默认显式设置构建接口的 `debug=false`，避免接口旧默认值增加无关变化。需要调试属性时核对当前 Apktool 的真实参数。
- `force`、清理和覆盖参数可能删除原目录，不默认复用已有输出目录。使用独立路径；清 framework 缓存也只在已定位缓存问题且范围获准时执行。
- Manifest、资源 ID、framework 依赖和 DEX 重组相互有关时，验证所选最小解码路径确实能表达修改。

## 归档与签名

工具可选 Uber APK Signer 或 Android Build Tools 等实际可用实现，未配置工具不等于已安装能力。

- 核对未修改条目的内容、压缩属性及必要对齐，保留非签名运行资源。签名工具负责替换其识别的旧签名；不要删除整个 `META-INF/`。
- 使用 `zipalign` 与 `apksigner` 时先对齐后签名，最后独立验证。页面大小、未压缩库和资源表要求按目标平台及本机帮助确定。
- 一体化工具也需要确认完成了所需对齐与验证；不因退出码成功忽略实际产物。
- 使用新输出文件，密钥身份明确，密码通过受控输入提供，不写入脚本、命令记录或普通日志。
- 包含多个签名方案不保证能覆盖安装原包；用相同设备上的原包、对照重签包和修改包区分错误来源。

修改方法与完成条件见 `../patch-and-verify.md`。完整集合处理见 `../topics/split-packages.md`。本技能不默认调用上游自定义重打包器。
