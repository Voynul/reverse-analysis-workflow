# mobile-mcp / ADB / 设备侧工具操作

先从已暴露接口选择实现，首次操作时确认设备与目标应用。设备变化后再验证；不把设备检查扩展成全部逆向工具的预检。

## mobile-mcp

- 先列本机可用设备；远程设备仅在用户同意其资源使用后分配。
- 元素存在于界面层次时优先使用最新 element ref；导航或布局变化后重新查询，不复用失效坐标。
- 截图显示尺寸可能小于实际屏幕，按工具提供的映射换算坐标。
- 冷启动、终止、安装、点击、输入按任务选择；Frida spawn 已启动进程时，不再无条件发起第二次启动。
- 使用可观测条件等待页面、Activity 或请求变化，无法观察时才使用有限的短等待。

## ADB 与设备 Shell

- 明确目标序列号，区分宿主 Shell 与设备 Shell 的引号和参数。简单命令优先使用参数数组，避免多层字符串拼接。
- 检查实际进程 ABI、应用 uid、当前前台和 package path；设备报告 ABI 不能代替目标进程证据。
- split 作为完整集合处理；覆盖安装、降级、数据保留和签名错误分别解释。
- 日志通过时间窗、PID、tag 和独立输出来源定位。不要自动清空日志或将旧崩溃归于新构建。
- 文件读写、权限修改、端口转发、代理和应用数据操作按任务范围执行；提权与内核变更遵守用户授权，不能由工具存在推导权限。

设备侧 MT/APK MCP 或 Termux 仅在实际可用时选择，接口以当前注册信息为准。设备操作方法见 `../mobile-automation.md`，环境排错见 `../topics/device-environment.md`。
