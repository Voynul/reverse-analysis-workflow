# 抓包服务与网络文件操作

工具选择不决定协议判断。Reqable 可用时使用其实际接口；也可处理用户提供的 HAR、流量文件或其他可用捕获实现。

## 当前接口的使用

- 先使用已暴露的工具清单；不用逐个健康检查服务。
- 当前 Reqable 提供 `capture_live_filter`、`capture_live_get_by_id`、`capture_live_generate_curl` 等接口时，按其 schema 筛选并获取完整记录。不要调用旧文档中的 `get_domains` 等未注册接口。
- 记录编号可能在新捕获会话中复用。关键证据同时保留 URL、时间、方向及可用会话身份。
- 需要启动捕获时确认实际捕获范围；只有任务需要时才启用。系统代理、设备代理、证书安装、重写、断点均是独立操作，不因读流量自动启用。
- HAR、WebSocket、原始报文或 gRPC 能力按实际接口确认。没有对应接口时可以使用提供的文件或其他工具，不编造工具名称。
- 要生成服务脚本时，先读取其脚本框架和模板，再编写符合当前对象模型的脚本。

## 数据与复现

获取关键请求时检查请求行、header、query、body、响应及编码是否完整。UI 展示、自动解压和文本转义可能改变可见形式；需要字节证据时保存原始形式及转换说明。

生成 cURL 或代码不等于已经执行请求。重放前核对任务范围、账户、环境和动作；脱敏后的文本不一定能直接复现。不得把连接超时、无响应或空捕获直接归因于服务端校验。

不会自动恢复或清除用户原有捕获记录。需要修改设置时记录任务所改项目，结束时仅处理本任务拥有的设置与产物。
