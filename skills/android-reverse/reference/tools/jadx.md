# 无头 DEX 静态工具操作

仅在选择对应工具后读取；分析经验见 `../static-analysis.md`。优先使用当前可用的 `jadx-headless`，也可使用 JEB、索引器或等价无头实现；具体命名空间由宿主解析。

## 目标与首次调用

- 用户选定的文件及从中明确定位的关联产物可以加载；多个候选无法区分时再澄清。不要沿用无关会话残留目标。
- 使用 `load_apk` 后核对 `current_apk`、可取得的 Manifest 身份与实际输入路径。已有会话首次使用时先核对当前目标，不必反复加载。
- 只在需要索引查询时检查 `index_status`；安全的真实读取本身也可完成连接验证。

## 查询完整性

- 如果工具提供 `coverage_complete`，结合它判断索引覆盖，不能只看 `ready`。覆盖完整仍不等于 Java 反编译全部成功。
- `get_class_source`、`get_method_by_name` 可能返回部分 Java 或 smali。检查实际返回类型、降级标记和质量统计，按真实来源引用。
- 搜索结果中的 `source_kind`、`source_note` 等字段存在时用于判断命中来源；没有该字段不自行补造。
- 文本按返回的下一页偏移继续；列表按实际 schema 的分页参数读取。缩小大查询范围，不能把单页当全量。
- 类名、字符串、调用关系和包结构查询按问题组合；不要求先全量导出或先完成整个索引。

## 故障与生命周期

- 中断后可做一次轻量只读检查；若明确超时或服务要求重启，保留进度，停止重复同一反编译。可用 smali 或其他无头工具补证。
- 服务由宿主管理，中间汇报和闲置等待时不主动关闭。用户明确要求关闭或释放进程内存时才调用 `shutdown_jadx`；发起退出不等于确认退出。
- `clear_cache` 不等于卸载目标或删除磁盘索引。stdio EOF 和 HTTP 常驻行为以当前服务实现为准，不承诺闲置自动退出。
- JEB 的类、方法、smali、交叉引用操作按当前 schema 使用，不移植旧 GUI 的当前选中项或窗口接口。
