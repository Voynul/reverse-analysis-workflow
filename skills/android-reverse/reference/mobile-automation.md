# 手机自动化规范

## 适用场景

- 启动、停止、冷启动、热启动 APP。
- 点击、滑动、输入、返回、切换前后台。
- 触发广告展示、登录、授权弹窗、页面跳转、网络请求。
- 截图确认 UI 状态。
- 配合 Frida 和 Reqable 批量采集运行时数据。

## 可选观察路线

1. 选择目标设备。
2. 确认目标 APP 包名。
3. 根据任务选择冷启动、热启动或指定页面操作。
4. 每次关键操作后等待界面稳定。
5. 需要证据时截图或记录 UI 元素。
6. 读取 Frida 日志和 Reqable 请求，与操作时间对齐。

## 操作与环境

元素、坐标、截图、ADB 与安装接口见 [设备工具](tools/device.md)。本节关注如何构成可比较的运行样本；进程状态和环境故障见 [设备环境](topics/device-environment.md)。

## 自动化模板

冷启动并触发页面：

```text
1. 选择并确认本轮冷启动条件。
2. 需要早期 Hook 时选择 spawn；否则在启动后的合适时机附加。
3. 核对目标已经启动，避免重复启动覆盖本轮条件。
4. 等待首页或开屏加载。
5. 获取界面元素或截图。
6. 点击目标按钮、Tab 或广告位。
7. 记录操作时间、截图和 Hook/抓包日志。
```

循环采集：

```text
1. 冷启动。
2. 等待预加载。
3. 浏览几个页面。
4. 切到后台。
5. 等待指定时间。
6. 回到前台。
7. 读取 Hook 日志和网络请求。
8. 重复 N 轮。
```

## 操作建议

- 优先用元素文本或描述定位；WebView 无法列出元素时使用坐标。
- 根据界面元素、Activity、截图变化或网络状态等待目标条件满足；无法观察条件时才使用有上限的短暂等待。
- 每次点击、滑动、输入都记录目的。
- 复杂流程写成可重复步骤，便于复现。
- 截图只证明 UI 状态，不直接证明代码逻辑；需要结合 Hook、抓包或反编译证据。
