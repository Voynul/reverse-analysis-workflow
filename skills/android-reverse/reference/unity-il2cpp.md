# Unity / Mono / IL2CPP 分析

## 何时读取

目标业务进入 Unity 托管程序集、IL2CPP native 实现或相关 metadata 时使用。先识别实际后端和问题所在层，再选择静态、运行时或资源分析；不要求启动 GUI、替换运行库或进行全量 dump。

## 区分后端与资源

| 候选形态 | 常见产物 | 分析入口 |
|---|---|---|
| Mono | `Assembly-CSharp.dll` 等托管程序集、Mono 运行库 | 使用可用的无头 CIL/C# 分析能力，追踪业务程序集及其 native 交接 |
| IL2CPP | `libil2cpp.so`、`global-metadata.dat` 或对应内存产物 | 将 native 实现与类型、方法、字符串等 metadata 关联 |
| Unity 资源 | AssetBundle、TextAsset、配置及其他资源包 | 先判断数据是否控制目标行为，再决定是否需要分析代码 |

文件名和默认路径只作线索。检查完整安装集合、实际加载来源及动态模块，避免将未找到默认文件直接解释为加密或业务不存在。`libunity.so` 等引擎产物也不能单独证明脚本后端。

## Mono 路线

从目标相关的托管类型、字符串、调用和资源引用定位业务逻辑；Android 壳、引擎和插件仍可共同参与。

程序集无法解析时，先区分文件截断、版本或工具不兼容、包装以及保护，不自动认定为加密。只有任务确需运行观测时再选择兼容的无头方式；不把桌面平台的运行库替换方案直接用于 Android。

## IL2CPP 的配对分析

- 确认 native 库和 metadata 属于同一应用构建，并核对 ABI、Unity/metadata 版本及文件完整性。混用版本可能生成看似合理的错误名称或偏移。
- 当前环境可用时，可以选择 Il2CppDumper、Cpp2IL 等解析能力；工具名是候选，具体输入、输出和版本支持以实际接口为准。
- 分开理解输出：类型与方法声明、DummyDll 或类似骨架用于导航，不是原始方法实现；函数地址和注解用于回到 native 代码。metadata 缺失会影响命名和映射，但仍可根据现有 native 证据继续分析。
- 将类型、字符串和地址信息导入无头分析环境时，检查导入器及目标数据库，按工具实际要求提供数据。JSON、头文件和脚本职责不同，不能把数据文件直接当可执行脚本运行。
- 选择可回查的类型、字符串或调用点核验映射。泛型共享、跳板或包装层可能使方法声明与机器码并非一一对应。

## metadata 缺失、异常或受保护时

| 现象 | 候选解释与补证方向 |
|---|---|
| 默认路径不存在或文件为空 | 检查 split、其他资源、嵌入载荷和实际加载来源；不能单凭空文件证明 metadata 一定只在内存中 |
| 魔数或头部异常 | 区分包装、截断、自定义布局、转换及加密；魔数正确也不能证明整个文件有效 |
| 版本可识别但解析结果异常 | 核对布局、表范围和对应 native 构建，避免只改版本整数使工具继续运行 |
| 静态文件与运行表现不一致 | 追踪 metadata 的加载、转换和消费时机，必要时观察实际被消费的缓冲区 |

需要运行取证时，记录缓冲区来源、长度依据、加载阶段和关联模块。按当前布局检查表的范围及引用，不使用某篇案例的固定头长、固定偏移或任意 dump 长度。

内存模块以实际映射、内容和加载证据确认，不默认选择第几段映射。dump 的运行时地址与 ELF 文件布局需要区分；保留原始 dump，再按分析工具所需重建或重定位，不能把所有段统一改成某种偏移关系当成通用修复。

## 运行观测与完成边界

需要行为证据且环境支持时，可以使用兼容的 IL2CPP 运行时接口或桥接工具缩小到目标类、方法或对象；不默认枚举全部对象或修改运行库。查不到类型时先检查加载时机、模块、版本和工具覆盖范围。

分别说明已取得类型信息、已定位实现、已观察调用、已复现算法或已验证修改。dump 成功不代替功能验证；后续分别参照 `native-analysis.md`、`algorithm-validation.md` 和 `patch-and-verify.md`。

方法参考：本地审阅的 `apk-reverse-codeberg-mirror` 中 `references/unity-runtime.md`、`references/il2cpp-protected-metadata.md`。上游部分路线尚无实测记录；它们可作为方法候选，当前目标的结论仍以实际证据确定。
