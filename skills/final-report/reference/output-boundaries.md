# 输出与修改边界

## 文件输出

最终报告必须输出为新版本文件，避免覆盖旧版。

推荐命名：

```text
final-analysis-report-v001.md
final-analysis-report-v002.md
final-analysis-report-v003.md
```

生成规则：

1. 每次生成前检查输出目录已有版本。
2. 新文件使用下一个可用版本号。
3. 不覆盖、不清空、不移动旧版最终报告。
4. 正文开头写明版本号、生成时间和生成目的。

## 修改边界

默认只读取：

- 普通分析报告。
- 阶段报告。
- 证据文件。
- 命名记录。
- 项目规则。

默认只生成：

- 新版最终报告。
- 必要时生成 `Question.md`。

默认不修改：

- 历史最终报告。
- 普通分析报告。
- 阶段报告。
- 命名记录。
- 原始证据文件。

只有用户明确要求重新分析或补证，并允许更新对应文件时，才修改普通分析报告、阶段报告或命名记录。

## 重新分析边界

表达不完整、章节不理想、措辞不统一，不构成重新分析理由，应该在最终报告中改写。

只有以下情况才进入补证分析：

1. 核心结论缺少证据。
2. 普通分析报告、阶段报告或原始证据之间存在无法解决的冲突。
3. 关键链路缺少上游触发或下游结果。
4. 用户明确要求重新分析。

补证仍需遵守证据规则和工具路由。
