# 内容取舍优先级

## 必须保留

1. 影响主链路的核心机制。
2. 启动、配置、请求、处理、展示、上报等关键流程。
3. 网络请求、响应字段、配置字段、加密或压缩字段。
4. 反编译代码、抓包数据、Hook 日志、配置文件、解密结果、native 分析支撑的结论。
5. 多份报告互相印证或存在冲突的内容。
6. 读者理解整体逻辑所需的模块关系。
7. 用户分层、环境分支、地区分支、实验分组、本地缓存分段等影响行为的条件。
8. 已检查但未发现、且与核心结论有关的机制。
9. 普通分析报告或阶段报告中的待确认问题和证据缺口。

## 可以归并但不得直接删除

1. 重复字段说明可以合并成一张表，但不同含义、不同来源、不同使用位置不能混为一条。
2. 重复调用链可以合并成主链路，但不同入口、触发时机和分支必须保留。
3. 公开 SDK 或通用库的常规初始化细节可以压缩，但影响主链路时必须保留。
4. 与主题弱相关但有证据的发现可以放入“其余内容单独总结”。
5. 大段代码可以截取关键判断，完整来源放入证据索引。

## 不得写入

1. 无证据支撑的猜测。
2. 阶段分析中的临时判断。
3. 与最终主题无关的工具操作过程。
4. 开发修复、重构、优化建议。
5. 安全、隐私、风险、合规等审计式评价。
