# 冲突处理规则

## 证据优先级

普通分析报告、阶段报告或原始证据之间存在不一致时，按以下顺序处理：

1. 原始证据优先于文字总结。
2. 反编译代码、抓包数据、Hook 日志、配置文件、解密结果、native 伪代码优先于推测性描述。
3. 最新分析优先于旧分析。
4. 证据更完整的报告优先于证据较少的报告。
5. 项目命名记录优先于各报告中的临时命名。
6. 无法确认时列为待确认，不自行调和。

## 冲突记录格式

| 冲突点 | 来源 A | 来源 B | 当前采用 | 采用原因 | 是否需要补证 |
|---|---|---|---|---|---|

## Question.md 触发条件

出现以下任一情况时，应生成或更新 `Question.md`：

1. 语义不详。
2. 数据冲突。
3. 逻辑或流程冲突。
4. 逻辑链路不完整。
5. 分析不够详细或缺少关键证据。
6. 技术方案或功能未说明白。

## Question.md 字段

| 字段 | 说明 |
|---|---|
| 问题编号 | 例如 `Q-001` |
| 问题类型 | 上方 6 类之一 |
| 涉及主题 | 初始化、配置、网络、Hook、native 等 |
| 涉及来源 | 报告路径、代码位置、日志位置、请求位置 |
| 当前已有说法 | 摘要说明已有材料怎么写 |
| 问题详情 | 写清哪里不清楚、冲突或缺证据 |
| 影响范围 | 影响最终报告哪个结论或章节 |
| 建议补充分析 | 补代码、补抓包、补 Hook、补字段、补 native 等 |
| 优先级 | 高 / 中 / 低 |
