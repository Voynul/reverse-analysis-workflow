# OpenMediation 项目规则

本文件是 `android-reverse` 的项目约束输入，用于收窄静态分析范围、明确重点证据和排除范围。它不是通用 skill。

## 分析对象

- APK 包名：`com.open.web.ai.browser`
- 重点 SDK：`com.openmediation.sdk`

优先聚焦自建广告聚合 SDK。

## 重点功能

- 广告预加载策略。
- 缓存管理。
- 竞价 / 比价调度。
- 按顺序尝试多个广告源的调度。
- 展示频次控制。
- 用户授权弹窗交互。
- 远程配置。
- 运行信息上报。
- 不同环境下的展示控制。

## 排除范围

以下公开聚合平台和广告源 SDK 只做边界确认，不深入其内部实现。仅关注它们被自建 SDK 调用的接口、接入方式和广告源列表。

公开聚合平台：

- `com.anythink.*`，TopOn。
- `com.tradplus.*`，TradPlus。
- `com.google.android.gms.ads.*`，AdMob。

广告源 SDK：

- `com.applovin.*`
- `com.vungle.*`
- `com.mbridge.*`
- `com.bytedance.*`
- `com.facebook.*`
- `sg.bigo.*`

## 证据和命名

- 命名记录：`rename.md`
- 混淆符号引用格式：`原名→新名`
- 关键判断、开关控制、流程分支、排序规则、频控规则、配置读取必须附反编译代码片段或等价原始证据。
- 证据不足时写入待确认问题，不得补猜测。

## 常见普通分析报告

- `result/analyze.md`：广告 SDK / 聚合平台概览。
- `result/network-analysis-report.md`：网络协议分析。
- `result/bidding-analysis.md`：竞价 / 比价策略分析。
- `result/preload-analysis.md`：预加载策略分析。
- `result/risk-control-analysis.md`：展示控制策略分析。
- `result/UMP_time-analysis.md`：用户授权弹窗冷启动时序分析。
- `result/cloaking-analysis.md`：不同环境展示不同内容分析。
- `result/data-collection-analysis.md`：运行信息上报分析。
- `result/delivery-strategy-analysis.md`：投放行为策略分析。

## 补证边界

最终报告合并任务默认只读取已有普通分析报告、阶段报告和证据文件。

只有以下情况才进入补证分析：

1. 核心结论缺少证据。
2. 报告之间存在无法解决的冲突。
3. 关键链路缺少上游触发或下游结果。
4. 用户明确要求重新分析。

如果当前任务不允许补证，应把问题写入 `Question.md`。

# OpenMediation 最终报告模板

本模板适用于 OpenMediation / 广告 SDK 类项目的最终汇总报告。它是项目模板，不是通用 `final-report` skill。

## 输出文件

推荐输出：

- `result/final-analysis-report-v001.md`
- `result/final-analysis-report-v002.md`

不得覆盖旧版最终报告。

如存在冲突、证据缺口或后续补充分析事项，额外输出：

- `Question.md`

## 必需章节

最终报告建议包含：

1. 总览。
2. 整体运行链路。
3. 核心问题说明。
4. 其余内容单独总结。
5. 关键配置与开关。
6. 关键链路图。
7. 已检查但未发现的机制。
8. 待确认问题。
9. 证据索引。

## 总览

用 5 到 8 条白话结论说明整体发现。每条结论必须可验证，并能对应后文核心章节。

## 整体运行链路

必须包含一张总流程图：

```md
图 1：整体运行链路
```

要求：

1. 使用 `mermaid` 的 `flowchart TD`。
2. 节点使用中文白话。
3. 不直接把原始类名、方法名放进节点。
4. 关键判断节点必须在正文模块中给出代码或原始证据。

## 核心问题说明

围绕以下核心点合并普通分析报告内容，不能按报告文件顺序简单拼接：

1. 接入广告聚合平台和广告源。
2. 广告 SDK 的初始化和用户授权弹窗的关系。
3. 广告预加载策略。
4. 广告预加载执行逻辑。
5. 广告比价逻辑或策略。
6. 广告展示条件控制。
7. 不同环境下的展示控制。
8. 投放行为策略。

每个核心点包含：

| 内容 | 要求 |
|---|---|
| 核心问题 | 用白话说明本节回答什么 |
| 触发时机 | 说明什么时候执行 |
| 关键判断 | 写清开关、条件、分支 |
| 合并来源 | 标注哪些普通分析报告或证据文件被合并 |
| 证据 | 附关键反编译代码、抓包、Hook、配置、解密或 native 证据 |
| 和其他核心点的关系 | 说明是否依赖初始化、配置、预加载、比价、展示控制或上报 |
| 一句话总结 | 小节末尾必须有 |

## 其余内容单独总结

放置与 8 个核心点关联不强、但仍有必要保留的内容。

可以放入：

1. 公开广告 SDK 的常规初始化细节。
2. 与自建广告聚合 SDK 关系较弱的广告源内部实现。
3. 与广告主链路无直接关系的应用业务接口。
4. 有证据但不影响核心结论的辅助发现。

不得放入：

1. 无证据支撑的猜测。
2. 为了保留而保留的过程性分析。
3. 开发修复建议。
4. 安全、隐私、风险、合规等审计式评价。

## 关键配置与开关

使用固定表格：

| 配置或字段 | 白话含义 | 影响范围 | 来源位置 | 证据 |
|---|---|---|---|---|

填写要求：

1. 配置或字段保留原文。
2. 白话含义必须简短。
3. 影响范围写清楚影响哪个流程。
4. 来源位置写类、方法、报告文件或证据文件。
5. 证据写反编译代码、抓包数据、Hook 日志、配置文件、解密数据或普通分析报告结论。

## 关键链路图

建议包含：

1. 启动链路图。
2. 用户授权弹窗与广告 SDK 初始化关系图。
3. 预加载策略图。
4. 预加载执行逻辑图。
5. 比价或排序链路图。
6. 展示条件控制链路图。
7. 不同环境下的展示控制图。
8. 投放行为策略图。

如果某条链路证据不足，必须标为待确认，不得补画推测流程。

## 已检查但未发现的机制

只保留与核心结论相关、或读者容易误以为遗漏的内容。

使用固定表格：

| 检查项 | 搜索关键词 | 搜索范围 | 结论 | 来源文件 |
|---|---|---|---|---|

## 待确认问题

只列证据不足或存在冲突的问题。如果问题需要后续分析补充，必须同步写入 `Question.md`。

使用固定表格：

| 问题 | 当前已有证据 | 不足之处 | 需要补充的分析 | 来源文件 |
|---|---|---|---|---|

## 证据索引

使用 `final-report/reference/evidence-index.md` 的字段和规则。
