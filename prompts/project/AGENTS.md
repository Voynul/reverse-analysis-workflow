# 可复用 Android 分析与报告工作约定

本文件适用于 Android 逆向分析、阶段报告生成、最终报告汇总类任务。项目级 `AGENTS.md` 可以补充具体 APK、包名、报告清单和业务重点，但不应削弱本文件的证据要求。

## 核心原则

1. 禁止假设和虚构。所有结论必须能回到反编译代码、抓包数据、Hook 日志、配置文件、解密结果或已有报告证据。
2. 数据操作必须使用真实数据。加解密、解析、字段映射、请求还原不得用占位符或示例数据冒充真实样本。
3. 混淆符号必须先解释再引用。无意义类名、方法名、字段名应根据功能重命名，并在报告中使用 `原名→新名` 格式。
4. 分析报告只描述已观察到的实现方式和行为，不写开发修复建议，不写安全、隐私、风险、合规等审计式评价。
5. 证据不足时写成“待确认问题”，不得把推测写成确定结论。

## 工具路由

- 静态分析：优先使用 JADX MCP；JADX 不足或需要交叉验证时使用 JEB MCP。
- 动态分析：使用 Frida MCP Hook 参数、返回值、加解密函数和运行时分支。
- 手机操作：使用 mobile-mcp 启动 APP、点击、滑动、输入、截图和切换前后台。
- 网络数据：使用 reqable MCP 获取请求、响应、域名、WebSocket 和 HAR 数据。
- Native 层：当 Java 层进入 `.so`，或用户明确要求分析 native 逻辑时，使用 ida MCP。
- MCP 工具不可用处理：如果任务需要某个 MCP 工具，但调用返回失败、工具未注册、命名空间不存在、连接失败或服务未启动，应明确提示用户检查对应 MCP 工具是否已开启，并带上工具调用失败原因。不要把 MCP 不可用误写成分析结论。

## 报告输出

- 普通分析报告和阶段报告使用 `analysis-report` skill。阶段报告使用 `analysis-report` 的阶段版。
- 最终汇总报告使用 `final-report` skill。
- Android 逆向分析使用 `android-reverse` skill，并在需要输出报告时叠加对应报告 skill 的规范。

## 自检

交付前必须检查：

1. 关键结论是否都有证据来源。
2. 混淆符号是否有可读名称和 `原名→新名` 记录。
3. 是否存在用猜测填补证据缺口的内容。
4. 报告是否使用中文白话说明，代码名和字段名是否保留原文。
5. 涉及流程、关系、状态或时序时是否配图。
6. 是否避免了开发建议和审计式评价。
