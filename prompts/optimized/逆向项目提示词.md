# Android 逆向项目提示词

本文件适用于 Android 逆向分析、普通分析报告、最终报告合并和报告审查类项目。它负责项目级路由和硬边界；具体执行细节交给 skill。

## 项目工作流

1. Claude 负责分析任务和普通分析报告。
2. Codex 负责最终报告合并和报告审查。
3. 小型任务可以只生成一份普通分析报告。
4. 大型任务先生成多份普通分析报告或阶段版报告，再合并最终报告。
5. 如果项目根目录提供了 `项目规则.md`，应作为 `android-reverse` 的项目约束接口输入，用于限定优先范围、排除范围、证据文件和输出要求；如果没有提供，则跳过项目约束，按用户问题和 APK 证据自然探索。

## Skill 路由

| 任务 | 使用 skill | 说明 |
|---|---|---|
| Android 逆向分析 | `android-reverse` | 静态分析、动态 Hook、抓包、手机操作、native 分析和证据链 |
| 普通分析报告 | `analysis-report` | 支持精简版、标准版、阶段版 |
| 最终报告合并 | `final-report` | 汇总多份普通分析报告、阶段报告和证据文件 |
| 报告审查 | `report-analysis-reviewer` | 检查证据、结构、冲突、输出边界和交付质量 |

## 项目约束接口

项目根目录可以额外提供：

```text
项目规则.md
```

该文件由用户按具体项目自行提供，不随通用安装脚本安装。可以包含：

- 分析对象。
- 优先分析范围。
- 排除范围。
- 重点功能。
- 已有报告清单。
- 命名记录路径。
- 最终报告项目模板。

存在 `项目规则.md` 时，`android-reverse`、`analysis-report`、`final-report` 和 `report-analysis-reviewer` 都应先读取并应用其中与自身任务相关的约束。不存在时跳过，不得自行编造项目约束。

## 核心边界

1. 所有结论必须能回到反编译代码、smali、抓包数据、Hook 日志、配置文件、解密结果、截图操作记录或 native 分析证据。
2. 加解密、字段解析、请求还原必须基于真实样本。
3. 混淆类、方法、字段、变量引用前必须先给出可读名称，并记录 `原名→新名`。
4. 报告只描述已观察到的实现方式和行为，不写开发修复建议，不写安全、隐私、风险、合规等审计式评价。
5. 证据不足时写入待确认问题，不把推断写成确定结论。
6. MCP 工具不可用时，应说明对应工具和失败原因，不得当作目标 APK 没有该逻辑的证据。

## 报告规则

1. 普通分析报告使用 `analysis-report`：
   - 精简版：单字段、单接口、单方法、单开关、单次 Hook 结果。
   - 标准版：一个完整专题、一条链路、一组字段、一个配置机制。
   - 阶段版：大型任务中的阶段产物，可供最终报告合并。
2. 最终报告使用 `final-report`，必须按功能主题重组，不按报告文件顺序拼接。
3. 报告审查使用 `report-analysis-reviewer`，优先列阻断问题。
4. `stage-report` 已退役；需要阶段报告时使用 `analysis-report` 阶段版。

## 命名与证据

1. 当前任务目录应维护 `rename.md`。
2. 报告引用混淆符号时使用 `包名.原名→新名`。
3. 不确定的命名可以加 `_TODO`，并写入待确认问题。
4. 复杂报告应维护证据索引，说明结论、证据类型、证据位置和是否已在正文引用。

## 图表与表达

1. 涉及流程、调用链、数据流、状态切换、网络时序或分支判断时必须配图。
2. 图表节点使用简短中文描述，不直接堆类名或方法名。
3. 关键分支、开关、排序、状态切换必须在正文中附代码、抓包、Hook 或 native 证据。
4. 标题、小节名、图表节点和总结尽量使用普通读者能理解的说法。
5. 代码名、字段名、类名、方法名、包名、URL、文件路径保留原文。
