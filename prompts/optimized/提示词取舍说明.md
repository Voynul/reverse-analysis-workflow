# 提示词取舍说明

## 你的问题：静态分析适用规范还需要放全局吗？

结论：不需要放在通用全局提示词里。

原因：

1. 静态分析适用规范是 Android 逆向领域规则，不是所有项目都需要。
2. 你已经有 `android-reverse` skill，其中包含静态分析、混淆命名、JADX/JEB 路由和证据要求。
3. 如果全局提示词也写一份，后续会出现 skill 和全局规则漂移。

推荐放置：

| 内容 | 应放位置 |
|---|---|
| 禁止虚构、真实数据、工具失败不是结论 | 通用全局提示词 |
| Android 逆向必须证据链、混淆命名、MCP 不可用边界 | 逆向项目提示词 |
| JADX/JEB 具体操作、`.source`、`toString()`、rename.md 模板 | `android-reverse` skill |
| 报告级别、图表、白话表达、证据索引 | `analysis-report` skill |
| 多报告合并、冲突处理、版本化输出 | `final-report` skill |
| 审查标准、阻断问题、交付判断 | `report-analysis-reviewer` skill |

## 全局提示词应该保留什么？

全局只保留跨项目永远成立的规则：

1. 不编造。
2. 使用真实数据。
3. 区分证据和推断。
4. 工具不可用不能变成业务结论。
5. 不默认覆盖历史文件。
6. 需要时读取项目提示词和 skill。

## 项目提示词应该保留什么？

项目提示词保留项目级路由和硬边界：

1. Claude 做分析和普通报告。
2. Codex 做最终合并和审查。
3. 逆向分析用 `android-reverse`。
4. 普通报告用 `analysis-report`。
5. 最终报告用 `final-report`。
6. 审查用 `report-analysis-reviewer`。
7. Android 逆向证据、命名、报告边界不能弱化。

## Skill 应该保留什么？

skill 放可复用的具体做法：

1. 工具路由。
2. 分析步骤。
3. 报告结构。
4. 输出自检。
5. 领域内的细节规范。

## 旧提示词如何处理？

建议：

1. `prompts/global/` 中旧的全局文件保留为平台模板。
2. `prompts/project/` 中旧的项目文件保留为历史参考。
3. 新工作优先使用 `prompts/optimized/通用全局提示词.md` 和 `prompts/optimized/逆向项目提示词.md`。
4. 等新提示词跑稳定后，再决定是否删除旧模板。
